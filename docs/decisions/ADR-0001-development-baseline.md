# ADR-0001 — MVP 개발 기준과 산출물 관리

날짜: 2026-10-07 / 상태: 개발 기준 채택 / 관련: I01~I09, C01~C12

## 배경

제품·인증·아키텍처 설명은 존재했으나 요구·정책·계약·검증 산출물의 기준 파일과 완료 상태가 분리되지 않았다. 사용자는 실제 개발 절차에 맞춰 산출물과 정책 파일도 만들도록 요청했다.

## 사용자 요구에 따른 기준

셀프 칭찬, 개인/공유 포도알 분리, 목표별 생성, 내 목표에 지인이 칭찬하는 공유판, 사람 계정 연결, 확장 가능성, 외부 도구 사용 허용은 직접 요구다. Git 연결은 추후 단계라는 요청을 유지한다.

Next.js·서버 세션·Supabase·RLS/RPC·Vercel 구성은 앞서 정한 기술 기준이다. 서비스 개설·배포 완료 상태와 구분한다.

## 이번에 선택한 개발 규칙

정책 JSON을 수치의 기준으로 만들고 제품 상태·생명주기·응답 범위를 파일로 정한다. 요구 ID와 API operation, TC, 개발 작업을 연결한다.

초기 20알·범위 1~100, 다음 회차 설정 적용, 목표 삭제 휴지통 30일, 복구 시 archived·판 권한 미복구, 탈퇴 시 즉시 접근 중단·철회 없음·24시간 정리 목표, 작성자 본문/참조 파기 후 수신 회차 이벤트 유지, 개인 메모 수정·공유 문구 수정 미제공, 숨김 복원 가능·제외 복원 미제공, UTC 하루 제한을 초기 개발 기준으로 선택했다.

이 선택은 기존 미결정 항목을 구현 가능한 기준으로 구체화한 것이다. 각 값의 효과는 정책 문서와 검증 계획으로 검토한다. 사용자 요구가 바뀌면 정책·ERD·API·TC를 함께 변경한다.

## 최초 가정의 해소와 출시 전에 필요한 입력

최초 기준 작성 시 가입 범위는 성인 개인 베타 가정이었다. 같은 날 사용자 답변으로 성인 개인 중심을 확정했으며, 현재 가입 기준과 변경 영향은 [ADR-0002](ADR-0002-adult-personal-audience.md)를 따른다. 보호자 모델은 후속 범위다.

운영 주체·지원 연락처·도메인·월 예산·실제 제공자 처리/보관 설정은 서비스 개설과 공개 정책 작성에 필요하다. 로컬 설계·기본 기능 구현과 병행해서 준비한다. 보관 기간은 개발상 상한이며 법적 의무를 검증한 인증 결과가 아니다.

## 결과

현재 설계 단계의 파일과 검사 증거를 마련한다. 실제 구현·SQL·RLS·E2E·복원·출시는 해당 단계에서 수행하고 실행 증거가 있을 때만 완료로 기록한다. 별도 서비스·유료 플랜·원격 Git은 이번 산출물 생성으로 만들어지지 않는다.

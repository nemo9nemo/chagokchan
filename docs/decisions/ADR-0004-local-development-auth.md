# ADR-0004 — 개발 작업 공간과 로그인 적용 시점

날짜: 2026-10-08 / 상태: 채택 / 출처: 사용자 명시 요구

개발의 기준 디렉토리는 `C:\Users\love0\nemo9Dev\chagokchan`으로 지정한다. 이전 작업 공간의 기획·정책·설계·검사 도구를 복사하고 파일 해시를 확인한다. 복사 후 개발과 상태 갱신은 지정 디렉토리에서 진행하며 이전 경로는 참고 사본으로 남긴다. Git 저장소 연결은 사용자 예정 시점에 별도로 진행한다.

개발 중 앱은 로그인 화면 없이 로컬 가상 사용자로 이용한다. 실제 로그인 제공자 연동과 로그인 테스트·실사용은 오픈 준비 시점부터 진행한다. 기존 로그인 정책은 출시 기준으로 유지한다.

로컬 서버가 합성 A/B/C의 실제 로컬 Auth 세션을 준비하는 사용자 해석 경계를 도입한다. 업무 RPC·RLS·계정 상태·현재 연결·차단·판 권한 검사는 개발 중에도 동일하게 적용한다. 브라우저가 actor UUID를 지정하거나 관리 키로 업무 권한을 우회하는 구조를 도입하지 않는다. 배포에는 실제 사용자 세션 모드를 요구한다. 구현 세부는 [로컬 개발](../development/local-development.md), 값의 기준은 [개발 정책](../../policies/development-policy.json)이다.

DB 설계 → 마이그레이션 → RPC·RLS 검증 → 서버 경계 → 개인 기능 → 공유 기능 순서로 개발한다. 실제 로그인은 기능 개발의 선행 조건에서 분리하고 출시 전 필수 검증으로 둔다. 로컬 가상 사용자 검사를 실제 로그인 검사의 통과로 집계하지 않는다.

작업별 상태는 [진행표](../development/backlog.md)를 기준으로 한다. 완료 시 해당 행에 완료 범위·산출물·검사 근거를 기록하고 사용자에게 갱신한 표를 보여준다. 상위 단계와 환경 상태는 [등록부](../development/artifact-register.json)에 맞춘다. 문서 작성 완료와 실행 코드·DB 검증 완료를 구분한다.

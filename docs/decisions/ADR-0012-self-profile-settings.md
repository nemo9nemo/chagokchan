# ADR-0012 본인 프로필 갱신과 공유 상대의 보조 표시

날짜: 2026-11-17 / 상태: 채택, 구현·수락은 진행표 W12-E 기준

## 배경

신규 계정의 기본 닉네임과 아바타가 같고 사용자가 이를 수정할 경로가 없다. 검토 문서의 새 API 이름은 예시이며 기존 계약에 PATCH /me가 이미 예정돼 있어 해당 경로를 재사용한다.

## 결정

첫 베타의 PATCH /me는 nickname·avatar_key만 허용하고 기존 Me 응답을 반환한다. timezone 변경은 미구현 후속으로 남긴다. 서버에서 확인한 사용자 ID와 결과의 사용자 ID가 같아야 하며, 일반 역할의 직접 DML을 열지 않는다. 기존 NOLOGIN RPC 소유자의 본인 행·열 갱신 권한과 고정 search_path·명시적 EXECUTE를 사용한다.

닉네임은 NFC 후 양 끝 ASCII 공백을 정리하고 기존 1~20 코드포인트 상한을 적용한다. 제어 문자·공백만 있는 값은 거절한다. 변경하지 않은 필드는 덮어쓰지 않고, 같은 필드 경합은 마지막 커밋이 이긴다. 삭제 접수와 같은 사용자 잠금 뒤 현재 세션·active 상태를 다시 검사한다. 기존 가입 기본값·확인 시각·정책 버전·시간대·목표·칭찬·권한은 유지한다.

닉네임의 전역 유일성을 새로 요구하지 않는다. 현재 권한으로 이미 조회 가능한 사용자 UUID의 마지막 12자리 대문자 16진수를 4자리씩 표시해 동명이인을 구분하는 보조 정보로 사용한다. 초대 미리보기에는 inviter_display_code 12자리만 추가한다. 전체 UUID나 메일을 UI에 추가 표시하거나 검색·연결 코드로 사용하지 않는다. 단축 표시는 충돌 가능성이 있고 신원/권한 증명이 아니므로, 사용자는 실제 지인에게 받은 초대인지 확인한다. DB의 사용자 UUID·연결·차단·판별 권한이 접근을 결정한다.

## 결과와 경계

프로필 테이블에 새 식별자 열·전역 닉네임 색인·추가 계정 상태를 만들지 않는다. 초대 미리보기 응답에 허용 필드를 추가하므로 신규 SQL·API의 정확한 필드 검사·OpenAPI·화면·검사를 같은 변경으로 맞춘다. 호스팅 DB 준비와 실제 수락을 로컬 구현 완료와 구분한다. [작업 범위](../plans/W12-E-profile-settings.md).

롤링 배포의 구버전 BFF를 위해 기존 미리보기 RPC의 두 필드 응답은 유지한다. 보조 표시가 포함된 별도 RPC `preview_connection_invite_with_profile`가 기존 검증 경로를 호출한 뒤 정확한 세 필드를 반환한다. 이미 적용한 SQL은 수정하지 않았으며 후속 SQL로 호환성을 복구한다. 신규 두 SQL을 호스팅에 적용할 때는 외부에 중간 projection이 노출되지 않도록 단일 트랜잭션으로 묶고 각각의 원본 해시를 기록한다.

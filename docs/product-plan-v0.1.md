## 제품의 중심 경험

**작은 실천이나 칭찬할 순간마다 포도알 하나를 채우고, 완성한 포도송이를 성취의 기록으로 남긴다.**

포도 모양, 칭찬 메모, 보상은 이미 경쟁 서비스에 있다. 첫 제품은 선택한 사용자가 쉽게 시작하고 반복해서 사용할 수 있는 흐름을 중심으로 설계한다. 차별화 여부는 실제 사용자와 경쟁 앱의 사용 흐름을 비교해 판단한다. [조사 근거](market-research-2026-10-07.md)

## 사용자별 제품 방향

| 대상 | 사용 예시 | 이 대상을 선택하면 먼저 필요한 기능 |
| --- | --- | --- |
| 부모·아이 | 아이가 장난감을 정리하면 보호자가 포도알을 주고, 둘이 진행 상황을 확인 | 쉬운 칭찬 입력, 아이가 읽기 쉬운 판, 보호자 편집 권한, 아이별 판 |
| 교사·학원 | 학생·모둠·학급이 약속을 지키면 칭찬판을 채우고 수업 화면에 표시 | 학생 목록, 빠른 부여·일괄 부여, 큰 화면, 학기별 보관 |
| 개인 | 독서나 운동을 실천하면 스스로 포도알을 붙이고 완성한 판을 모음 | 빠른 기록, 목표별 판, 편한 수정, 기록 복원, 완료판 모음 |

초기에는 한 대상을 중심으로 문구와 첫 사용 흐름을 정하는 것을 제안한다. 부모·아이를 첫 대상으로 선택할 경우, 한 기기를 함께 쓰는지 서로 다른 기기를 쓰는지를 다음으로 확인한다.

## 공통 사용 흐름

1. **판 만들기:** 칭찬판 이름과 포도알 개수를 정한다. 보상은 선택한다.
2. **포도알 붙이기:** 주요 버튼을 눌러 다음 빈 포도알을 채운다. 날짜·시간은 자동으로 남긴다.
3. **칭찬 남기기:** 자주 쓰는 문구를 선택하거나 짧게 적는다. 기록 입력은 대상에 맞게 선택 또는 필수로 정한다.
4. **모인 성취 보기:** 채운 개수와 남은 개수를 확인하고, 포도알을 눌러 당시 기록을 읽는다.
5. **판 완성:** 축하 화면과 전체 기록을 보여준다. 보상이 있다면 약속 이행 상태를 기록한다.
6. **다음 판 시작:** 완성한 판은 보관하고 같은 설정으로 새 판을 만든다.

일상 예시 — 부모·아이를 선택할 경우: ‘스스로 준비하기’ 10알 판을 만든다 → 오늘 가방을 챙긴 순간 포도알 1개와 칭찬 문구를 남긴다 → 10알을 모으면 함께 칭찬 기록을 돌아본다 → 미리 정한 보상이 있다면 함께 실행한다 → 완성판을 보관하고 다음 판을 시작한다.

## 첫 버전 공통 범위 제안

| 기능 | 구체적인 동작 | 검증할 이유 |
| --- | --- | --- |
| 칭찬판 생성 | 이름, 목표 개수 10·20·30알 선택, 선택형 보상 입력 | 처음 시작하는 과정의 부담 확인 |
| 진행 중인 판 목록 | 판별 진행 개수 표시, 최근 사용한 판 쉽게 열기 | 원하는 판을 빠르게 찾는지 확인 |
| 포도알 추가 | 주요 버튼으로 다음 칸에 1개 추가, 짧은 반응 표시 | 칭찬하는 순간에 바로 기록할 수 있는지 확인 |
| 칭찬 기록 | 날짜·시간 자동 저장, 문구 선택·메모, 알별 상세 보기 | 입력 부담과 기록의 가치 확인 |
| 수정·실수 취소 | 최근 추가 실행 취소, 기록 편집 | 잘못 눌러도 사용을 이어갈 수 있는지 확인 |
| 완료판 보관 | 완료 날짜·판·칭찬 내역 유지, 새 판 복제 생성 | 완료 경험이 다음 사용으로 이어지는지 확인 |
| 기록 복원 | 기기 변경·앱 재설치 상황을 고려한 저장·백업 방식 | 성취 기록이 오래 유지되는지 확인 |

아이별 판·학생 목록·일괄 부여·공동 편집은 대상에 따른 첫 버전 범위다. 특히 두 보호자의 공동 사용이나 교실 일괄 부여를 선택하면 해당 기능을 첫 버전에 포함한다.

| 내 칭찬판 | 진행 중인 판 선택 | 제목, 채운 개수, 마지막 기록, 새 판 버튼 |

| 칭찬 기록 | 문구 선택·기록 읽기·수정 | 자주 쓰는 문구, 메모, 날짜, 수정 |

## 기록 규칙 제안

- 기본 칭찬판은 칭찬할 때마다 1알을 채우는 방식으로 제안한다. 개인의 매일 실천이 중심이면 하루 한 번 규칙을 따로 검토한다.
- 목표 개수에 도달한 판은 완료 상태로 바뀐다. 새 기록은 다음 판에 남긴다.
- 완료판의 실수 기록을 취소해 목표 미만이 되면 진행 중으로 되돌린다. 이미 이행한 보상이 있다면 변경 사실을 확인할 수 있게 한다.
- 새 판 시작은 완료 기록을 보관한 뒤 새 판을 만드는 동작이다.
- 지난 날짜의 실제 실천을 늦게 기록하는 기능은 대상과 사용 이유를 확인한 뒤 결정한다.
- 보호자가 칭찬을 주는 구조에서는 보기와 편집의 권한을 구분한다. 아이의 직접 완료 요청 기능을 선택하면 보호자 승인 여부를 함께 정한다.
- 공동 사용을 선택하면 동시에 같은 칭찬을 기록하는 상황과 기기별 변경 충돌을 처리할 규칙이 필요하다.

## 저장·공동 사용·플랫폼 결정

| 실제 사용 조건 | 설계 제안 | 플랫폼 판단 |
| --- | --- | --- |
| 한 사람이 한 기기에서 사용 | 빠른 시작, 기기 저장, 복원 가능한 백업 | 모바일 중심 시제품으로 핵심 흐름 검증 후 앱·웹 결정 |
| 부모·아이가 한 기기를 함께 사용 | 보기·편집 역할 전환, 보호자 설정 | 휴대폰·태블릿 화면을 함께 검토 |
| 여러 보호자·아이의 기기에서 공동 사용 | 사용자 초대, 공유 권한, 동기화, 변경 기록 | 공동 사용이 첫 버전 요구면 계정·동기화도 첫 버전에 포함 |
| 수업 중 교사가 표시하고 관리 | 학생 목록, 일괄 부여, 큰 화면, 기록 보관 | PC·태블릿 웹을 우선 후보로 검토 |

‘가입 없이 시작’은 시작 속도를 높이는 후보이며, 가족 공동 사용에 필요한 계정을 대신하지 않는다. 플랫폼·프레임워크·서버 선택은 대상과 공동 사용 조건을 정한 뒤 진행한다.

## 후속 버전 후보

완성판 이미지 공유·출력, 다양한 판 테마, 홈 화면 위젯, 선택형 알림, 가족 공동 편집, 학급 협동판, 주간 기록 보기, 현실 보상 관리 등을 검토한다. 공동 편집·학급 협동판 등이 핵심 사용 조건으로 선택되면 첫 버전으로 앞당긴다.

게임 캐릭터·가상 재화·보상 상점·AI 일기·소셜 커뮤니티는 별도의 제품 방향과 운영 범위를 요구하므로 사용자의 선호를 확인한 뒤 결정한다.

## 검증 계획

대상 확정 후 해당 사용자 5–10명에게 화면 시안을 보여주고, 가능하면 7일간 작은 범위의 시제품을 사용하게 한다. 아래 수치는 초기 설계 목표이며 시장 평균이나 검증된 성과가 아니다.

| 확인할 항목 | 초기 목표·관찰 방식 |
| --- | --- |
| 첫 판 만들기 | 설명 없이 1분 안에 만들고 첫 포도알을 붙이는지 관찰 |
| 반복 입력 | 이미 열린 판에서 기본 추가는 1회 탭, 문구 선택을 포함해 10초 안에 끝나는지 관찰 |
| 진행 이해 | 현재 개수·남은 개수·완성 조건을 스스로 설명하는지 확인 |
| 기록 가치 | 알별 칭찬 기록을 다시 보고 싶어 하는지 확인 |
| 완료 경험 | 첫 판을 완료한 뒤 다음 판을 시작하려는 이유 확인 |
| 실제 반복 사용 | 7일 동안 예정한 칭찬·실천 순간에 사용했는지와 놓친 이유 기록 |
| 경쟁 제품 대비 가치 | 같은 과정을 가까운 경쟁 제품과 비교하고 선택 이유 확인 |

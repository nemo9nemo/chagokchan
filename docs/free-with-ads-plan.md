# 차곡찬 무료 이용·광고 수익 모델 검토

기준일: 2026-10-19 / 작업: W22-B / 상태: 비교 기록 보존, 사용자 후속 결정으로 수익화는 출시 후 부차 검토

최신 우선순위: 사용자가 “앱 출시가 목표, 부수익은 서브”로 정했다. 아래 광고안은 비교 기록이며 첫 출시의 필수 조건이 아니다. 광고·유료 상품의 구현으로 출시를 지연하지 않는다. [실제 출시 사례와 현재 실행 순서](release-first-launch-review.md)를 우선한다.

사용자가 무료 이용과 광고 수익 방식을 질문했다. 핵심 기능 무료 + 선택형 꾸미기 보상 광고를 우선 검토하는 안을 권한다. 유료 구독을 출시 필수 조건으로 두지 않는다. 광고 도입 자체·사업자 계정·실제 노출 위치는 아직 확정하거나 구현하지 않았다. 출시 순서는 [모바일 웹/PWA → Android → iOS](launch-and-growth-plan.md)다.

## 이용 경험과 배치

차곡찬은 짧게 기록하고 나가는 사용을 예상하므로 광고 노출 기회가 제한될 수 있다는 제품 판단이다. 실제 이용 시간·광고 수용도·DAU를 측정하기 전에는 매출을 예측하지 않는다.

| 방식 | 권고와 조건 |
| --- | --- |
| 핵심 기능 무료 | 현행 정책 범위의 목표·기록·개인/공유 칭찬·연결·차단·삭제를 광고 시청 없이 제공한다. 기존 정책 상한을 이 문서만으로 바꾸지 않는다. |
| 선택형 보상 광고 | 별도 꾸미기 화면에서 “광고 시청 완료 시 새 테마 24시간 이용” 같은 명시적 보상을 시험하는 후보. 실제 추가 테마·이용권·만료·중복 지급 방지 구현 후 가능하다. 기존 기본 테마는 무료로 유지한다. |
| 배너 | 유용한 독립 콘텐츠가 있는 화면에서만 후보를 검토한다. 현재 기록·목표 목록의 노출 적격성을 가정하지 않는다. 화면 하단 배너를 기본값으로 넣지 않는다. |
| 전면 광고 | 초기 시험에서 제외한다. 칭찬마다, 저장 직후, 앱 시작/종료에 강제 노출하지 않는다. |
| 광고 제거·테마 구매 | 반복 이용과 불편 피드백이 확보된 뒤 검토할 선택지. 가격·판매·결제 코드는 미구현이다. |

보상 광고는 행동·보상을 먼저 알리고 사용자가 선택해야 한다. 거절·중단·광고 없음·네트워크 실패가 기본 사용을 막으면 안 된다. 보상은 본인만 앱 안에서 쓰는 비현금성 꾸미기로 한정한다. 광고로 칭찬 개수·회차 완성·목표 실천량·공유 권한을 바꾸지 않는다. 이는 차곡찬의 제품 경계이며 Google이 테마 보상을 사전 승인했다는 뜻이 아니다. [Google 보상 정책](https://support.google.com/admob/answer/7313578?hl=en)

내용이 없거나 가치가 낮은 화면, 알림·이동 목적 화면에는 Google 광고 제한이 있다. 로그인·초대·오류·빈 상태·저장 완료 알림에는 배치하지 않는다. 버튼 가까이 광고를 두어 오클릭을 유도하지 않는다. [콘텐츠 없는 화면 정책](https://support.google.com/publisherpolicies/answer/11112688?hl=en) · [전면 광고 제한](https://support.google.com/admob/answer/6201362?hl=en)

## 플랫폼별 순서

| 단계 | 실행 범위 |
| --- | --- |
| 1차 로컬 | 계획·수익 계산만 준비한다. 광고 SDK·외부 광고 요청·사용자 추적을 추가하지 않는다. |
| 2차 모바일 웹/PWA | 실제 로그인·제품 수락 후 무료 베타로 첫 기록과 재방문을 확인한다. 웹 광고는 콘텐츠·사이트 심사와 개인정보 경계를 별도로 검토한다. PWA라는 이유만으로 AdSense 승인을 보장하지 않는다. |
| Android | 앱 포장 방식을 정할 때 AdMob 연동 가능성을 함께 검증한다. TWA만 추가했다고 네이티브 광고 SDK가 연동되는 것은 아니다. 필요하면 SDK를 지원하는 앱 구조를 비교해 W23에서 결정한다. 테스트 광고로 검증한 뒤 운영 광고를 분리한다. |
| iOS | Android의 수용도·유지율·실제 수익을 보고 W24에서 검토한다. SDK 수집 정보·동의·추적 여부·스토어 공개와 실제 기기 동작을 확인한 뒤 도입한다. |

[AdSense 사이트 준비 기준](https://support.google.com/adsense/answer/7299563?hl=en) · [AdMob Android 테스트 광고](https://developers.google.com/admob/android/test-ads)

광고에 목표 제목·칭찬 본문/태그·지인·이메일·초대 비밀·인증 쿠키를 전달하지 않는다. 광고 스크립트가 기록 화면의 DOM과 인증 영역을 읽을 수 있는 방식도 도입 전에 검토한다. 단순히 분석 payload를 비우는 것만으로 충분하다고 보지 않는다. 실제 수집·동의 거부 시 동작·SDK 데이터 공개를 설계하고, 인증/사용자 응답의 PWA·공유 캐시 금지 원칙을 유지한다.

## 수익 산술과 민감도

월 추정 광고 수익 = **평균 DAU × 1인 하루 실제 광고 노출 수 × 30일 ÷ 1,000 × eCPM**. DAU는 하루 활성 사용자 수이며 MAU와 다르다. eCPM은 게시자 수익 기준 1,000회 노출당 추정액이다. 요청 수가 아니라 실제 노출 수를 사용한다. 노출 기회로 계산하면 fill/show 비율을 먼저 반영하고 실제 노출 수에 다시 곱하지 않는다. [Google eCPM 정의](https://support.google.com/admob/answer/15337570?hl=en)

아래 **하루 2회 실제 노출·eCPM 1,000원은 시장 평균이 아닌 임의 계산 가정**이다. 보상 광고를 선택하지 않는 사용자와 미충전·미노출도 평균 노출 수에 포함해야 한다.

| 평균 DAU | 월 실제 노출 가정 | 월 추정 광고 수익 |
| --- | --- | --- |
| 100명 | 6,000회 | 6,000원 |
| 1,000명 | 60,000회 | 60,000원 |
| 5,000명 | 300,000회 | 300,000원 |
| 10,000명 | 600,000회 | 600,000원 |

DAU 1,000명·하루 실제 2회로 고정하고 가상 eCPM을 500/1,000/3,000원으로 바꾸면 월 30,000/60,000/180,000원이다. 배너·보상 광고의 노출/단가는 형식·국가·동의 상태·시기에 따라 따로 관찰한다. 위 가정을 그대로 쓰면 월 운영비 150,000원을 충당할 평균 DAU는 2,500명, 월 광고 수익 1,000,000원에 필요한 평균 DAU는 올림 16,667명이다. 세금·추가 운영비·인건비·수익 조정 전이며 보장액이나 실제 견적이 아니다. 인앱구매 수수료 15%를 이 광고 수익에 기계적으로 차감하지 않는다.

## 시험과 판단

먼저 광고 없는 베타에서 첫 기록·D7 유지·사용 불편을 확인한다. 이후 충분한 표본과 수집/동의 준비가 있으면 일부 사용자에게 선택형 보상 광고를 시험한다. 노출·선택·완료·보상 지급·실패·실제 수익과 첫 기록/D7 변화를 함께 본다. 광고 수익이 늘어도 저장 실패·오클릭·이탈이 늘면 중단한다. 빈 광고 자리를 채우려고 기록이나 클릭을 강요하지 않는다. 실사용 광고 클릭을 개발 검증에 쓰지 않는다.

마케팅의 **광고비 0원**은 사용자를 모집하기 위해 지출하는 비용의 제안이다. 여기서 검토하는 앱 내부 **광고 수익**과는 별개다. 무료 베타 모집과 콘텐츠 계획은 [마케팅 준비물](marketing/launch-kit.md)을 따른다. 구독/꾸미기 판매는 [이전 비교안](launch-and-growth-plan.md)의 후보로 유지하며 현재 판매 약속으로 쓰지 않는다.

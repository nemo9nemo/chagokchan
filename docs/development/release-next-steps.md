# 실제 공개까지 남은 작업

2026-11-17 / 현재 작업 기준은 [진행표](backlog.md)다. 출시용 스키마·웹 인증/제품 화면·삭제 작업자·로컬 암호화 백업/복원 기반이 있지만 실제 공개는 완료하지 않았다.

| 순서 | 작업 | 현재 상태·완료 조건 |
| --- | --- | --- |
| 1 | 운영 DB 나머지 적용·권한 검증 | 실제 27/56개 적용, 29개 남음. 스테이징은 56개. 사용자 작업/권한 승인은 받았지만 공급자 실행 확인이 표시되지 않고 만료됨. 같은 승인 범위로 재개하고 전체 이력·RLS·직접 DML·함수 소유자/경로를 검증해야 함 |
| 2 | 호스팅 삭제 원장·작업자·자동 백업/복원 | 로컬 worker 8건·전체 복원 7건 검증. 실제 서버의 독립 원장·정기 실행·보관/키 복구·목표/취소 이력·접수 직후 장애 경계·복원 후 작업자 재개 수락은 남음 |
| 3 | 분산 요청 제한·남용 방어 | 여러 서버에 걸친 제한, 직접 Auth 요청 방어, 장애 시 중요 쓰기 503, 반복 초대/로그인/칭찬 남용 검증 필요. 무료 WAF 조사와 실제 제한 적용 완료를 구분 |
| 4 | 실제 Google 로그인·제품/정책 수락 | 공통 공개 지원 이메일을 받은 뒤 제공자 연결. 실제 가입·성인 자기 확인·갱신/로그아웃·다른 계정/탭·초대/공유 권한 회수·재인증/탈퇴·캐시/모바일 수락. 운영 연락처/표시·처리방침 확정 |
| 5 | 운영 배포·공개 확인 | 같은 검증 소스를 운영 환경에서 빌드·비파괴 검사 후 공개 주소 연결. 실제 로그인/권한/삭제·운영 복원 수락을 통과해야 함 |

사용자가 먼저 준비할 것은 앱 이름과 독립적인 공통 공개 지원 메일 주소다. 새 주소를 문의처·Google 로그인 지원 주소로 쓴다. 개인 로그인 이메일이나 Git 작성자 이메일을 임의 대입하지 않는다. 비밀번호나 인증번호는 채팅으로 받지 않는다. 운영 DB 작업 승인은 재요청하지 않으며 공급자 확인 창 문제와 구분한다.

현재 운영 DB의 Auth/앱 사용자는 0명이다. 18개 제품 테이블 모두 RLS를 강제하고 일반 역할 직접 DML·익명 definer 실행·내부 역할 전환은 0건이다. 파기 worker 설정 자체가 아직 운영 DB에 없으므로 이를 ‘gate false로 운영 검증 완료’라고 표시하지 않는다. 스테이징의 worker 설정은 존재하지만 호스팅 원장/작업자 수락과는 별도다. [읽기 전용 점검 근거](../quality/reports/w14-d1-production-progress-check-2026-11-17.json)

Supabase 임시 권한은 중단된 실행 재개 전과 최근 실행 종료 후 원래 기본 설정 상속으로 복구/재조회했다. 첫 중단 당시 즉시 원복은 관측되지 않았으므로 처음부터 계속 제한됐다고 주장하지 않는다. 실패한 SQL의 적용 이력은 없으며 같은 SQL을 다른 도구로 숨겨 실행하지 않았다. 기존 적용 SQL·사용자 데이터·유료 플랜을 변경하지 않는다.

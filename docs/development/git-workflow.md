# 기능 단위 커밋과 변경 기록

기준일: 2026-10-08 / 출처: 사용자 명시 요구

코드 작업은 기능 또는 독립적으로 검증 가능한 개발 기반 단위로 커밋한다. 변경한 기능과 이유를 제목·본문에서 확인할 수 있어야 한다. 관련 소스·검사·정책·계약·DB 마이그레이션·잠금 파일·진행 상태를 같은 단위로 기록한다.

## 커밋 시점

1. 해당 단위의 구현과 필요한 검사를 끝낸다.
2. 진행표·검사 근거·변경 기록을 갱신한다. 일부만 끝났으면 상위 작업은 진행 중으로 유지한다.
3. diff와 포함 파일을 확인하고 비밀·빌드 결과·로컬 데이터를 제외한다.
4. 검증한 변경만 지정해 커밋하고 커밋 해시·작업 내용·이유·검사 결과를 사용자에게 보여준다.

서로 다른 기능을 한 커밋에 섞지 않는다. 공통 기반과 해당 기능을 분리할 수 있으면 기반을 먼저 검증·커밋한다. 미검증 업무 기능을 완료한 기능처럼 커밋하지 않는다. 환경 문제로 DB를 못 실행한 경우 앱 기반 검증 결과와 DB 미실행을 구분한다.

## 메시지 형식

```text
feat(praise): 개인 칭찬 기록을 원자적으로 저장해 재시도 중복 방지

작업: 개인판 칭찬·집계·완성 처리와 중복 요청 검사를 구현했다.
이유: 같은 요청의 재전송과 동시 요청으로 개수가 잘못 늘어나는 것을 막기 위해서다.
검증: 관련 DB·API 시나리오의 실제 명령과 결과를 적는다.
참조: 해당 W / REQ / POL / TC를 적는다.
```

type은 feat·fix·chore·docs·test·refactor, scope는 기능이나 개발 영역을 사용한다. 제목에 작업의 목적을 담고, 본문의 작업·이유·검증은 실제 결과로 작성한다. 위 예시는 메시지 형식이며 칭찬 기능 완료의 증거가 아니다.

로컬 commit-msg 훅은 제목 형식과 작업·이유·검증·참조 본문이 있는지 확인한다. 의미와 실제 검증 결과의 확인은 개발자가 수행한다. 훅은 소스에 포함하고 저장소별 core.hooksPath로 연결한다.

## 저장소 범위

2026-10-08 사용자 지정 [nemo9nemo/chagokchan](https://github.com/nemo9nemo/chagokchan)을 origin으로 연결했다. 저장소는 공개(public), 기본 브랜치는 main, 업스트림은 origin/main이다. 기존 세 커밋의 이력을 유지해 첫 업로드를 완료했다. [연결 증거](../quality/reports/git-remote-connection-2026-10-08.json)와 [변경 기록](../changes/2026-10-08-git-connection.md)에 확인 결과를 남겼다.

기능 단위의 검증·커밋 후 원격 상태를 확인하고 일반 push로 올린다. 업로드 뒤 로컬 HEAD와 원격 main의 SHA·업스트림·작업 공간 상태를 확인한다. 원격에 다른 변경이 있으면 fetch 후 내용을 확인하며 강제 push로 덮어쓰지 않는다. CI·브랜치 보호·클라우드 배포는 별도 완료 기준으로 관리한다. 실제 .env·Auth 자격증명·로컬 개인 데이터·로그는 커밋하지 않는다.

진행 기준은 [진행표](backlog.md), 전체 운영 절차는 [배포·Git](../deployment-and-git.md)이다.

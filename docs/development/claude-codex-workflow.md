# Codex 직접 진행·검토 절차

기준일: 2026-10-19 / 출처: 사용자 명시 요청 “claude 사용하지 말고 해”

Codex가 기획·설계·구현·소스 검토·검증·진행 기록을 직접 담당한다. 기존 파일 경로는 링크 호환을 위해 유지한다. [AGENTS.md](../../AGENTS.md)와 [ADR-0007](../decisions/ADR-0007-codex-only-workflow.md)이 현재 기준이다.

## 현재 흐름

| 단계 | 수행과 근거 |
| --- | --- |
| 범위 확인 | 사용자 요구, 요구사항·정책·계약·진행표를 확인한다. 기존 브리프를 지시받으면 범위와 금지 사항을 따른다. |
| 설계·구현 | 요구 → 정책 → 설계·계약 → 검증 시나리오 → 구현 순서로 필요한 파일을 함께 갱신한다. 일반적인 선택을 별도 승인 대기로 만들지 않는다. |
| 직접 검토 | diff와 호출 문맥, 권한·집계·재시도·데이터 보존 등 해당 변경의 위험을 점검한다. 지적·조치·잔여 한계를 남긴다. |
| 검증 | 변경에 필요한 실제 명령을 실행하고 소스·환경·결과·실패·미실행을 기록한다. 문서만 바꾸면 링크·형식·상호 참조를 확인한다. |
| 완료 | [진행표](backlog.md)·등록부·검사 근거를 갱신하고 [커밋 규칙](git-workflow.md)대로 커밋·push한다. main은 PR과 필수 CI를 거친다. |

Claude 실행·인증 복구·Claude APPROVED는 진행 조건이 아니다. 같은 Codex가 수행한 검토를 독립적인 교차 리뷰로 표현하지 않는다. 기존 브리프의 `Codex 구현 보고`에는 변경 파일·실행 명령/결과·미실행 검사/이유·직접 검토 결과를 남긴다. 실제 로그인·운영 입력·제품 수락·배포 게이트는 그대로 적용한다.

로컬 실행은 [runtime-setup.md](runtime-setup.md)의 고정 Node·pnpm과 `scripts/project.ps1`을 사용한다. 실행 제한이 있으면 안전한 범위에서 해결하고 결과를 기록한다. DB/API 검사를 다른 도구에 넘겼다고 실행 완료로 보지 않는다. 전역 probe·fixture snapshot을 쓰는 DB 검사는 순차 실행한다.

## 과거 기록

2026-10-13에는 Claude 기획/리뷰와 Codex 구현을 나누었다. 당시 브리프의 승인·리뷰·실행 증거는 역사적 사실로 보존한다. 2026-10-19 W21 Claude 리뷰 시도는 조직의 `oauth_not_allowed_for_organization` 403으로 모델 실행 전에 차단됐다. 이후 사용자가 Claude 사용 중단을 명시해 Codex가 직접 검토했다. 실패한 시도를 승인이나 완료 리뷰로 바꾸지 않는다. 기존 `.claude` 설정·플러그인을 제거하거나 재인증하지 않았다.

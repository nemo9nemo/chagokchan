# 1차 로컬 무로그인 마무리 기록

기준일: 2026-10-19 / 작업: W21 / 상태: 1차 로컬 무로그인 마무리 완료·Codex 직접 검토

사용자가 1차는 로그인 없이 마무리하고 2차에서 실제 로그인과 출시를 진행하기로 정했다. 단계 경계는 [출시 실행안](../launch-and-growth-plan.md), 작업 상태는 [진행표](backlog.md), 실행 증거는 [W21 보고서](../quality/reports/w21-local-closeout-check-2026-10-19.json)를 따른다.

## 1차 결과물

- 로컬에서 로그인 화면 없이 합성 A/B/C의 실제 Auth 세션으로 같은 RPC·RLS 사용.
- 목표·개인/공유 칭찬·태그·회차·연결/판 권한·소식·보낸함·목표 휴지통·복구 화면.
- 오류/재시도·같은 멱등 키·개인/공유 독립 집계·테마·정적 전용 캐시 경계.
- 고정 실행 도구 선택과 순차 검증 명령, 실제 실행한 검사의 환경·소스 근거.

1차 앱 주소는 `http://127.0.0.1:3000`이며 `.\scripts\project.ps1 -Task dev`로 실행한다. DB가 꺼져 있으면 먼저 `db:start`를 실행한다. 기존 fixture를 초기화하거나 개발 주소를 외부에 공개하지 않는다. 최초 환경 준비는 [실행 방법](runtime-setup.md)을 따른다.

## 검사 중 확인하고 고친 문제

| 문제 | 처리 |
| --- | --- |
| 번들 pnpm이 11.25.0으로 바뀌어 고정 11.19.0 실행 실패 | 프로젝트 안의 Corepack 캐시/실행 파일로 고정 버전을 선택. Node와 중첩 pnpm도 함께 고정 |
| 임시 정책 검사 RPC 생성 직후 PostgREST schema cache에 아직 없어 PGRST202 | 해당 임시 RPC에만 최대 10초간 누락 signature 재확인. 업무/권한 오류는 재시도하지 않음 |
| 공유 권한 회수 경합 검사에서 앞선 쿼터 소진 결과가 개입해 PT429 | 경합 시나리오는 새 합성 공유판을 사용. 제품 쿼터·권한·SQL은 변경하지 않음 |
| 등록부·README·인계에 이미 승인된 W09-D/W20-B/W10-D가 대기로 남음 | 최종 Claude 리뷰와 기록된 검사 근거로 현재 요약 동기화. 과거 보고 내용은 이력으로 보존 |

로컬 DB 검사는 전역 실패 트리거와 전체 fixture snapshot을 사용하므로 동시에 실행하지 않는다. 이번 실행에서 두 검사를 겹친 1회는 다른 검사에 `test_fault`와 snapshot 불일치를 만들었다. 검사 계정·실패 트리거 잔존 0을 확인했고, 이후 10종 96개를 순서대로 다시 실행해 모두 통과했고 기존 fixture·세션 보존과 probe 정리를 확인했다. 실패한 시도를 통과 횟수에 더하지 않는다.

## 2차에 남기는 범위

W12/W13 실제 Google/OTP·가입 확인·세션 갱신/로그아웃·재인증과 W10-C 계정 탈퇴 사용자 동선은 구현·수락 전이다. W14 운영 입력·실제 삭제 원장, W15 전체 제품 수락·실기기 확대/스크린리더/터치·계정 전환 PWA·백업 복원·부하는 공개 전에 필요하다. 설치형 Android/iOS와 결제/유료 상품도 기획 이후의 별도 구현이다.

TC-UI-MOCKUP-001의 전체 수락은 기존 계획처럼 W15에서 수행한다. 과거 부분 브라우저 검사를 전체 통과로 올리지 않는다. W21의 새 브라우저 검사는 실행한 화면·쓰기·폭·상태만 따로 기록한다. 실제 제공자 로그인 검사는 0건이며 로컬 가상 계정 결과로 대체하지 않는다.

기존 목표에 공유판을 나중에 추가하는 API와 초대 오류 세부 사유의 완전한 구분은 미구현이다. 현재 UI는 공유판을 목표 생성 때 선택하고, 서버가 합친 초대 오류 코드를 임의로 세분화해 추측하지 않는다. 이 제약과 추가 테마/회고·구독 후보를 완료 기능으로 광고하지 않는다.

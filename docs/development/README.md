S03의 ERD 완료는 실제 DB 생성 완료가 아니다. S04에서 도구·로컬 DB를 준비한 다음, S05에서 물리 제약·인덱스·마이그레이션과 RPC/RLS를 적용·검증한다. 각 기능 검사는 S06의 해당 기능 구현과 함께 수행하고 실제 로그인 검사는 S07에서 추가한다.

## 기능 작업의 준비 조건

- 관련 REQ와 수락 기준을 특정할 수 있다.
- 적용 POL·권한·삭제·오류 규칙이 정해져 있다.
- 필요한 ERD·API·화면 계약이 같은 기준을 따른다.
- 정상·무권한·중복·동시성 중 관련 TC가 있고 재현할 환경을 준비할 수 있다.
- 외부 설정이 필요한 부분과 로컬에서 끝낼 부분을 구분한다.

설계에 남은 설명상의 모호함은 작업 중 기준 파일에 구체화한다. 공개 출시 입력이 없는 상태로도 로컬 구현은 진행할 수 있다. 연령 범위가 바뀌어 보호자 모델이 필요해지는 경우에는 관련 정책·ERD를 먼저 변경한다.

## 기능 작업의 완료 조건

코드·마이그레이션·계약·정책·관련 문서가 일치하고, 해당 기능에 필요한 검사가 실제로 통과해야 한다. 실패·미실행 항목은 상태와 이유를 기록한다. 검사가 끝나면 소스 식별자·환경·실행 명령·결과를 [변경 기록](../templates/change-record.md)에 남긴다.

## 변경과 릴리스

### POL-OPS-001 — 재현·증거·환경 분리

Node·pnpm·패키지 버전과 잠금 파일을 고정하고 SQL·RLS·RPC 변경을 마이그레이션으로 관리한다. 로컬·스테이징·운영 설정과 비밀을 분리하고 소스·검사·마이그레이션·배포 ID를 연결한다. 실행하지 않은 결과를 완료로 표시하지 않는다.

큰 정책·아키텍처 선택은 docs/decisions에 ADR로 남기고 관련 REQ·POL·TC·API를 갱신한다. Git 연결 전에도 변경 기록과 검사 증거를 남긴다. Git 연결 후에는 같은 변경을 한 PR에서 검토한다.

출시는 [배포 절차](../deployment-and-git.md)와 [릴리스 기록](../templates/release-record.md)을 사용한다. 기획 보드나 플러그인 설치를 실제 서비스 구현·배포 완료로 기록하지 않는다.

# W12-A 배포 요청별 세션 경계와 출시 우선 전환

- 날짜: 2026-10-19 / 기준 소스: `46e875896914f202fc38d6e4272819d5a5cd6ade`
- 참조: REQ-001·NFR-001, POL-ACCOUNT-002·POL-SEC-001, TC-AUTH-002 중 세션 경계 부분
- 사용자 결정: 앱 공개 출시가 주목표, 수익화는 부차 목표. Codex 직접 리뷰·PR·CI·병합까지 진행

## 변경·이유

로컬 fixture 전용이던 32개 제품 route의 세션 진입부를 공통 요청별 어댑터로 연결했다. 배포에서는 암호화 Host 쿠키를 읽고 Auth.getUser의 검증 UUID와 get_me의 현재 DB 세션/활성 계정을 확인한다. 공유된 인증 클라이언트나 관리 키를 쓰지 않는다. 로컬 A/B/C는 기존 실제 로컬 세션을 사용하며 로그인 화면을 추가하지 않았다. API 입출력·업무 RPC·SQL·집계/권한 정책은 바꾸지 않았다.

배포 CSRF는 현재 세션 쿠키의 해시에 묶고 다른 계정·쿠키 교체 뒤의 이전 토큰을 거절한다. 기존 Origin·Fetch Metadata·서명 이중 제출·본문 제한은 유지한다. /auth/csrf의 구현 설명과 환경 변수 템플릿을 맞췄다. 일반 요청에 암묵적 갱신을 추가하지 않았다.

Daily·ABGT250·Linear의 당사자 출시 회고와 Play/TestFlight 공식 요건을 확인해 작은 범위·비공개 베타·단계적 공개 계획을 기록했다. 광고·구독을 출시 게이트에서 제외했다. 운영 형태·지원·도메인·예산·개발자 계정은 사용자 답변대로 미정이며 실제 개설/과금/배포는 하지 않았다.

## 검증과 한계

실행 명령·환경·결과·직접 검토는 [W12-A 보고서](../quality/reports/w12-a-session-check-2026-10-19.json)를 따른다. 새 단위 검사는 쿠키 변조·출처/키 분리·만료·다른 UUID·폐기된 DB 세션·의존성 오류·응답 allowlist·CSRF 세션 교체를 다룬다. 로컬 통합은 새 Auth A/B 세션을 실제 발급해 격리·JWT 위조·기간 만료·로그아웃 거절을 확인하고 새 세션만 정리한다. 기존 제품 테이블은 읽기 전용이며 snapshot과 기존 세션 수를 비교한다.

W12-A는 실제 Google/OTP·메일 전달·가입 bootstrap·갱신/로그아웃 엔드포인트·재인증·전체 제품 수락의 완료가 아니다. TC-AUTH-002 전체는 not_run을 유지한다. 쿠키 발급 헬퍼는 서버 내부 기반이며 새 로그인 동선을 공개한 것으로 보지 않는다. [진행표](../development/backlog.md)와 [ADR-0008](../decisions/ADR-0008-deployed-session-boundary.md)에 다음 단위를 구분했다.

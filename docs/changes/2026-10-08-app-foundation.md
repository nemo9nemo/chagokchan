# W04 앱 실행·환경 검사 기반

- 날짜: 2026-10-08
- 목적: DB와 업무 기능을 구현하기 전에 재현 가능한 앱 실행·환경 경계를 준비한다. 개발 중 로그인 입력을 생략하는 요구를 로컬 전용 모드로 구성하고 배포에서 해당 모드를 거절한다.
- 관련 기준: NFR-004, NFR-005, POL-OPS-001, POL-DEV-001. TC-DEV-002 중 환경 설정 차단 부분에 대한 단위 검사를 실행했다. 업무 API·스테이징·번들 검사까지 포함한 전체 TC는 미실행이다.
- 기준 소스: [검사 JSON](../quality/reports/foundation-check-2026-10-08.json)의 파일별 SHA-256·종합 digest. 로컬 Git 기능 단위 커밋에 소스·검사·설정·문서·상태를 함께 기록한다.

## 변경과 영향

Next.js·React·TypeScript·Tailwind 앱 기반과 테마에 의존하지 않는 준비 화면을 만들었다. Node·pnpm·의존성을 고정하고 잠금 파일을 생성했다. Biome 린트, 타입 검사, 환경 검사와 오프라인 빌드 명령을 제공한다.

로컬 환경에서는 A/B/C 설정, 실행 모드, loopback 바인딩, 앱/DB 주소·포트를 검사한다. 배포 환경에서는 실제 세션 모드를 요구하고 가상 사용자 설정을 거절한다. 실제 Auth 세션·제품 권한·API·목표 기록은 이 변경에 구현되지 않았다. 제품 정책과 ERD의 의미는 유지한다.

Supabase CLI로 로컬 설정을 생성했다. 새 테이블 자동 공개를 끄고 JWT 만료를 900초로 설정했으며 seed는 W05까지 비활성화했다. Docker 임시 소켓 문제를 복구한 뒤 실제 DB를 시작했다. 네트워크 기본 설정만으로 공개 포트가 제한되지 않는 문제는 Windows CLI 시작 요청에 loopback을 적용하고 실제 포트를 재검사하는 코드로 해결했다. 공개 바인딩이면 프로젝트 서비스를 중지한다. 필요한 로컬 서비스 7개를 실행한다.

## 실제 검사 결과

| 검사 | 결과·범위 |
| --- | --- |
| 설치·잠금 파일 | 실제 의존성 설치, 고정 버전 확인 |
| `pnpm run check` | 린트·타입·환경/포트 단위 27/27·산출물 상호 참조 통과 |
| `pnpm run build:check` | 외부 서비스 연결 없는 정적 컴파일 통과 |
| `pnpm run dev`·HTTP·수신 주소 | 127.0.0.1:3000, HTTP 200, 한국어·브랜드·보안 헤더 확인 |
| `pnpm run db:init` | 실제 CLI 실행·config.toml 생성 확인 |
| `pnpm run db:start`·DB/HTTP/포트 확인 | 기동 성공. PostgreSQL 17.11, Auth·REST 200, 공개 포트 모두 127.0.0.1 |
| 제품 수락 TC·DB·실제 로그인 | 0건 실행. 계획한 36개 TC는 not_run 유지 |

실행 환경과 검사 시각·소스 digest·HTTP·DB 연결·서비스별 포트 근거는 검사 JSON에 기록한다. 환경 검사 20개와 포트 회귀 검사 7개이며 제품 수락 TC와 구분한다. 실행 방법은 [개발 환경](../development/runtime-setup.md)을 따른다. 원시 로그·비밀·로컬 데이터는 Git에서 제외한다.

판=목표 1:1을 유지하면서 빈 상태·목록·판 만들기·내 판을 흑백 바탕과 순차 포도 그래픽으로 바꿨다. 공유 켬 생성은 같은 이름·알 개수로 기존 POST /goals 한 번에 처리한다. 공유 없는 판은 상태 안내만 표시한다. 개인/공유 탭과 지난 회차·설정·상태 전이·휴지통 기능을 유지한다.

입력은 760px 이하 native modal 하단 시트, 그 이상 그래픽 옆 패널이다. 실제 /me 닉네임과 현재 날짜·시간은 편집 없이 표시하고, 실천일 접힘·고정 태그 단일 선택·메모를 제공한다. 성공 전에는 집계/그래픽/목록을 바꾸지 않으며 실패 입력과 불확실 요청 키를 유지한다. 성공 후 응답 bunch_id를 재조회하고 최신 praise ID를 검사해 1회 pop/방금 또는 완성 안내를 표시한다. reduced-motion은 정지 링/저장됨을 사용한다. 기록 상세와 취소 확인 시트로 기존 정리 동작을 옮겼다.

공유 패널은 전체 초대 메타 조회, 새 코드의 마스킹·보기/숨기기·복사·개별 폐기와 기존 grant/revoke를 제공한다. secret은 패널 상태만 사용하고 닫으면 제거한다. 비동기 생성 중 닫힌 패널의 응답은 상태에 넣지 않는다. 생성 실패 후 메타를 다시 읽되 원문을 복구할 수 없음을 알린다. 연결과 판 권한이 별개임을 안내한다.

서버는 초대 세부 오류를 STATE_CONFLICT/OBJECT_NOT_AVAILABLE로 통합한다. 활성 5개 재조회·메타 상태로 확인 가능한 경우만 구분하며 받은 코드의 실패를 세부 사유로 항상 구분할 수 없다. 서버 API/계약 변경은 브리프 밖이므로 적용하지 않았다.

Node 24.19.0, pnpm 실제 11.25.0/고정 11.19.0, Biome 2.5.15, TypeScript 5.9.3에서 lint/typecheck/126 unit/산출물 검사를 통과했다. pnpm 명령은 버전 검사에서 실패해 지정한 직접 명령을 사용했다. project.ps1의 check/build:check/API 3종도 버전 검사에 막혔다. 직접 build-check는 컴파일 후 TypeScript 단계 spawn EPERM, 직접 API 3종은 로컬 앱 선행 종료로 완료하지 못했고 Docker 엔진 접근은 권한 거부였다. 실패 첫 줄과 실행 명령은 [검사 증거](../quality/reports/w20-b-mockup-ui-check-2026-10-15.json)에 기록한다.

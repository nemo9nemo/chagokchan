# 승인된 운영 DB 적용 진척과 남은 공개 조건

W14-D1 / REQ-010·NFR-001·NFR-004 / POL-SEC-001·POL-DELETE-003 / TC-OPS-CATALOG-001

사용자의 명시적인 운영 DB 역할/권한·검토 SQL 적용 승인과 적용 중에만 Supabase 플러그인 전체 허용 후 원복 승인을 반영했다. 기존 검증 main 2ade280의 SQL을 수정하지 않고 실제 이력에서 이어서 적용했다. 처음 3개에서 18개로 진행된 뒤 중단됐고, 재개해 27개까지 적용했다. 다음 `20261008023100_news_goal_trash_and_purge_rpcs.sql`은 공급자 확인 요청이 10분 뒤 만료되어 미적용이다. 29개가 남아 있으며 작업 승인 대기로 표시하지 않는다.

공급자 실행 확인은 별도 승인 창이 사용자에게 보이지 않는다는 답변을 받았다. 기존 브라우저 연결도 이 채팅에서 사용할 수 없다는 결과였으므로 Dashboard 실행을 완료했다고 표시하지 않는다. Supabase 플러그인 권한 변경은 사용자에게 정확한 임시 범위를 확인한 뒤 적용했고 재개 전·최근 실행의 finally에서 기본 설정 상속으로 복구한 뒤 조회했다. 첫 중단 시 즉시 원복은 확인하지 못했다.

새 읽기 전용 catalog SQL은 운영의 27개와 스테이징의 56개를 구분한다. 두 환경의 제품 테이블 RLS 18/18·일반 직접 DML 0·익명 definer 실행 0·내부 역할 전환 0·고정 경로/비로그인 소유자를 확인했다. 운영의 worker 구성은 아직 없고 스테이징의 내부 예약/완료 테이블은 RLS를 강제한다. 사용자 행·키·토큰을 반환하지 않는다. 새 제품 기능·실제 Google·운영 원장/복원·분산 제한·공개 배포를 완료한 것으로 표시하지 않는다.

# W11-B2 모바일 화면·조작 영역 후속 검사

- 작업 ID·제목: W11-B2 작은 화면·대비·모바일 조작 영역
- 날짜·담당: 2026-10-09 / Codex
- 변경 목적·전후 동작: 작은 화면에서 테마, 목표 추가, 초대, 새로고침, 재시도 조작부가 20~42px였다. 760px 이하 앱 버튼과 버튼 링크·아이콘·체크 행을 최소 45px로 넓혔다. 320px 브라우저 에뮬레이션에서 데스크톱 스크롤바 폭만큼 공간을 예약하던 `body` 최소 폭도 반응형으로 바꿔 문서 가로 넘침을 제거했다.
- 관련 REQ / POL / TC: REQ-011·NFR-002 / POL-SEC-001 / TC-WEB-005 기존 대비 검사 유지, TC-WEB-006 부분 뷰포트 검사·실기기 수락 미실행
- 정책·데이터 영향: 화면 CSS만 변경했다. 네 메뉴 이동과 목표 폼 열기만 확인하고 폼을 제출하지 않았다. 목표·칭찬·권한 데이터를 쓰지 않았다.
- 실행 환경·도구 버전: Windows 로컬, Node 24.19.0·pnpm 11.19.0·Next.js 16.4.0, Codex In-app Browser viewport override. 앱은 `http://127.0.0.1:3000`에서 실행했다.
- 실행 명령 또는 수동 재현 단계: 데스크톱 브라우저 viewport override로 관찰된 콘텐츠 폭 320/345/360/375/412/641px의 목표 목록·상세·연결·받은 공유판·휴지통을 순회했다(폭마다 5화면, 총 30회). 320px은 override 335px로 스크롤바를 보정했다. 로컬 Supabase를 loopback에서 기동하고 순서 있는 마이그레이션 49개(20261008013000~20261008024900)를 적용한 뒤 문서화된 `db:seed`로 합성 A/B/C 데이터를 준비했다. `api:me-test`는 A 세션에서 15/15 통과했다. 앱 조회 API 성공 응답과 화면 로드를 확인했고, 목표 생성 폼은 열기만 한 뒤 취소했다. 제품 데이터 쓰기는 제출하지 않았다. `scripts/project.ps1 -Task check`는 lint 96 files·typecheck·unit 115/115·JSON 40·링크 502·OpenAPI 경로 55/참조 700·등록 경로 290 검사를 통과했다. `scripts/project.ps1 -Task build:check`는 Next.js 16.4.0 production build와 40 route entries를 통과했다.
- 관찰 결과·증거 파일: 30/30 화면에서 문서 폭과 콘텐츠 폭이 일치하고 가로 넘침이 없었다. 목표 목록 화면의 네 메뉴가 표시되고 목표 상세는 뒤로 가기 조작을 표시했다. 노출된 앱 조작부 최소 측정 높이는 44.98px(설정값 45px)이었으며 44px 미만은 없었다. 320px 목표 생성 폼도 입력·체크 행·버튼이 화면 안에 있었다. 연결 화면은 합성 연결 1개를 렌더링했고 받은 공유판·휴지통은 정상 빈 상태를 표시했다. 접근성 트리에서 본문 건너뛰기 링크·제목·메뉴를 확인했다. 실제 음성 안내나 터치 하드웨어 동작은 확인하지 않았다.

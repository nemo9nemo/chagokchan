# 판 로딩 지연 측정과 개선

작업: W26-A / REQ-002·NFR-001·NFR-003·NFR-005 / POL-ACCESS-001·POL-API-001·POL-SEC-001 / TC-PERF-BOARD-001

목록 카드별 추가 HTTP 요청과 상세→모든 과거 회차→기록의 대기를 줄였다. 새 소유자 전용 일괄 RPC/API는 기존 목록·상세의 현재 세션·권한·필터·커서·필드 검사를 재사용한다. 기존 API는 유지하며 캐시나 인증 유효 결과의 TTL을 추가하지 않았다. 새 마이그레이션만 적용해 총 53개다.

현재 판은 신선한 상세 확인 뒤 먼저 표시하고 과거 회차는 비동기로 읽는다. 선택한 과거 회차 딥링크와 늦은 이전 응답을 구분하고, 이전 판의 칭찬 목록은 전환 시작 때 지운다. 과거 조회 장애가 현재 판을 지우지 않도록 했다. 개발 서버는 loopback의 주요 GET 경로만 미리 준비한다.

로컬 기존 판 1개·준비된 경로 8회 비교 중앙값: 목록 카드 165→77.3ms, 현재 판 준비 175→98.1ms. 목록 HTTP는 2→1개(최대 20개 카드의 구조는 21→1개이나 최대 용량 부하 실측은 아님). 이 수치는 HTTP/클라이언트 상태 전이 모형이며 브라우저 페인트·운영 응답 SLO를 뜻하지 않는다. 최초 10.8초 지연 중 10.7초는 개발 컴파일이었다.

unit 188·DB 406(신규 16)·실제 로컬 Auth A/B/C 통합 6·build-check를 통과했다. 통합 검사에서 모든 기존 제품 행·세션 보존과 새 검사 세션만 제거함을 확인했다. computer-use 앱 제어 승인 시간 초과로 실제 브라우저 검사는 미실행이다. 실제 IME/접근성·운영 최대 용량·부하 수락과 구분한다.

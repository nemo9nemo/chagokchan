# Google 재인증과 웹 계정 삭제 접수

W12-D2 / REQ-001/010·NFR-001 / POL-ACCOUNT-002·POL-DELETE-002·POL-SEC-001 / TC-DELETE-BFF-001

현재 계정의 검증된 세션으로 별도 Google PKCE를 시작한다. 같은 UUID의 새 세션에서만 서버 증명과 10분·1회용 삭제 grant를 발급하고 이전 세션을 폐기한다. 다른 계정을 선택하거나 기존 세션이 폐기된 경우 원래 앱 쿠키를 교체하지 않으며 새 보조 세션만 폐기를 시도한다. 원래 세션을 다시 받은 잘못된 교환 결과도 거절하며 그 세션은 폐기하지 않는다. Google 비밀번호 재입력을 보장하지 않는다.

계정 메뉴에서 삭제 화면을 열고 재인증한 뒤 복구 불가 확인과 삭제 요청을 따로 제출한다. CSRF·Origin·고정 scope·사용자/세션·흐름 쿠키·멱등 키를 검증한다. DB RPC가 deleting 전환과 grant 소비를 함께 처리한다. 응답이 불확실할 때 클라이언트는 같은 요청 번호를 재사용한다. 같은 멱등 요청의 현재 처리 상태도 API 계약에 명시했다.

접수 뒤 Auth 전체 세션 폐기를 시도하고 Auth·CSRF·로그인·초대·재인증 쿠키를 정리한다. 접수 번호만 암호화한 10분 HttpOnly 쿠키로 접수 안내를 제공한다. 202와 화면은 접근 차단·삭제 접수만 의미하며 실제 파기 완료와 구분한다. Auth 장애가 있어도 DB의 삭제 중 계정 검사는 제품 접근을 차단한다. 운영 worker·독립 원장·실제 파기는 W14에 남아 있다.

검증과 미실행 범위는 [검사 증거](../quality/reports/w12-d2-deletion-web-check-2026-11-09.json)를 따른다. Codex가 서버 경계·React effect 정리·확인 폼·멱등 키·쿠키 정리와 실패 처리를 직접 검토했다. 실제 Google·HTTPS·브라우저 삭제 동선 수락 전에는 공개 준비 완료로 취급하지 않는다.

Vercel은 사용자가 팀 접근을 승인해 같은 팀/프로젝트 조회가 정상화됐다. 연결 도구는 요금제 필드를 제공하지 않아 무료 플랜은 아직 별도 확인이 필요하다. 프로젝트는 배포 0건이며 과금·보호 해제·플랜 변경은 수행하지 않았다. 지원 메일은 특정 앱이 아닌 여러 앱 공통 주소를 사용하려는 사용자 의사에 따라 실제 생성 주소를 기다린다.

# W08-A 목표 생성·상세·수정 API

- 작업 ID·제목: W08-A, 개인 목표 생성·본인 상세·revision 수정 API 연결
- 날짜·담당: 2026-10-08, Codex
- 변경 목적·전후 동작: 기존 W06 goal RPC는 있었지만 Next.js 서버 route가 없어 제품 API 계약을 호출할 수 없었다. local fixture Auth 세션을 서버에서 재사용하고 목표 생성·상세·수정 route를 RPC에 연결했다.
- 관련 REQ / POL / TC / API operation: REQ-002, NFR-001, POL-GOAL-001, POL-GOAL-002, POL-ACCESS-001, POL-API-001, POL-SEC-001, TC-API-003, `createGoal`, `getGoal`, `updateGoal`.
- 정책·데이터 영향: 브라우저 입력 actor·owner UUID는 받지 않는다. create는 UUID `Idempotency-Key`를 필수로 하고 create/get/update 업무 RPC만 사용한다. 응답은 OpenAPI 필드 allowlist로 축소하고 no-store·request ID를 반환한다. 실제 배포 Auth session adapter는 W12다.
- 구현 파일: `src/server/goal-api.mjs`, `src/server/local-user-session.mjs`, `src/app/api/v1/goals/route.ts`, `src/app/api/v1/goals/[goal_id]/route.ts`, `scripts/goal-api.test.mjs`, `scripts/test-local-goal-api.mjs`.
- 실행 환경·도구 버전: Windows loopback Supabase, PostgreSQL 17.11, Node 24.19.0, pnpm 11.19.0, Next 16.4.0.
- 실행 명령: `scripts/project.ps1 -Task check`, `scripts/project.ps1 -Task build:check`, `scripts/project.ps1 -Task api:goal-test`를 A/B/C 각각 실행.
- 관찰 결과·증거 파일: [W08-A 검사 증거](../quality/reports/w08-a-goal-api-check-2026-10-08.json).
- 통과 / 실패 / 미실행: handler·allowlist 단위 8/8, check unit 61/61, A/B/C local API 각 3/3, build:check 통과. A/B/C API 검사는 미존재 목표 GET 404·잘못된 UUID 400·CSRF 없는 POST 403으로 DB를 변경하지 않았다. 실제 route→DB 성공 호출은 로컬 fixture 제품 데이터를 바꾸지 않도록 미실행이며, 해당 DB RPC는 W06에서 별도 검증했다. 실제 로그인·목표 목록·상태 전이·칭찬 API와 UI도 미실행이다.
- 다음 의존 작업: W08-B1에서 소유 목표 keyset 목록 RPC/API를 추가 완료했다. 이어서 W08-B2에서 목표 상태 전이·판 설정·회차 읽기를 연결한다. W08-C는 개인 칭찬·회차 쓰기 API, W08-D는 기본 화면이다.

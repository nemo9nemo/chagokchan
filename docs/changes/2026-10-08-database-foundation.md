# W05 — 목표·칭찬 데이터의 물리 관계와 로컬 준비

작성일: 2026-10-08 / 상태: SQL·로컬 초기 데이터·물리 제약 검사 완료. 업무 RPC·세션·화면은 후속 작업이다.

DB 적용 전에는 논리 ERD와 API 계약만 있었다. 제품 13개·보조 5개 테이블, 소유자/판/회차/수신자 복합 FK, 중복·상태·길이 CHECK, 조회/정리 인덱스를 [순서 있는 마이그레이션](../../supabase/migrations/20261008013000_product_schema.sql)으로 구현했다. 테이블 간 자동 삭제를 막고 모든 테이블의 RLS·직접 접근 거절을 기본값으로 삼았다.

관리 API로 표시된 합성 Auth A/B/C를 준비하고 A 개인·공유판, A/B 연결과 B의 공유판 권한을 명시적인 로컬 seed로 생성했다. 토큰은 저장하지 않고 임의 자격증명은 Git 제외 파일에 접근 제한을 적용해 보관한다. 반복 실행이 초기 상태로 되돌리지 않으며, 다른 환경은 준비 전에 실패한다. [물리 설계·명령·경계](../development/database-foundation.md)

| 항목 | 실행 결과 |

검사 7의 첫 입력은 잘못된 소유자와 중복 판을 동시에 만들었다. DB가 중복 제약을 먼저 보고해 예상 오류 코드가 달랐으므로, 판이 아직 없는 별도 목표로 외래키 검사를 분리했다. 적용한 마이그레이션은 변경하지 않았으며 수정한 51개 검사를 재실행해 통과했다. 테스트는 ROLLBACK해 기존 초기 데이터와 접근 권한을 보존한다.

환경: Node 24.19.0·pnpm 11.19.0·Supabase CLI 2.120.0·SDK 2.117.3·PostgreSQL 17.11·Docker 29.1.3. SDK와 하위 패키지는 잠금 파일에 고정하며 pnpm이 기록한 정확한 버전 예외도 함께 관리한다.

실행: `db:migrate`, `db:seed`, `db:test`, `check`, `build:check`, `pnpm install --frozen-lockfile`. 기준 부모 커밋은 `25abf5e`; 현재 소스 해시·SQL 버전·검사 시각과 범위는 [DB 검사 증거](../quality/reports/physical-database-check-2026-10-08.json)에 남긴다.

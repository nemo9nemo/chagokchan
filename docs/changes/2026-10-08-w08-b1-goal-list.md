# W08-B1 내 목표 목록 RPC·API

- 작업 ID·제목: W08-B1, 소유 목표 목록과 status-bound keyset pagination
- 날짜·담당: 2026-10-08, Codex
- 변경 목적·전후 동작: 목표 생성·상세·수정 API는 있었지만 개인 목표 목록 route/RPC가 없어 앱에서 소유 목표를 페이지로 읽을 수 없었다. 실제 Auth 세션의 소유자로 제한하고 필요한 요약 필드만 내보내는 DB RPC와 GET route를 추가했다.
- 관련 REQ / POL / TC / API operation: REQ-002, NFR-001, POL-GOAL-001, POL-ACCESS-001, POL-SEC-001, TC-API-004, `listGoals`.
- 정책·데이터 영향: 기본 limit 20, 최대 50. created_at·id 내림차순 keyset을 쓰고 cursor에 status 필터를 저장해 서로 다른 필터 간 재사용을 거절한다. 사용자·소유자 ID 입력은 없으며 deleted 목표는 반환하지 않는다. API 역할에 제품 테이블 직접 SELECT를 허용하지 않는다.
- 구현 파일: `supabase/migrations/20261008024300_goal_list_rpc.sql`, `supabase/migrations/20261008024400_goal_list_cursor_base64_wrap_fix.sql`, `supabase/tests/009_business_rpc_goal_list.test.sql`, `src/server/goal-api.mjs`, `src/app/api/v1/goals/route.ts`, `scripts/goal-api.test.mjs`, `scripts/test-local-goal-list-rpc.mjs`, `scripts/test-local-goal-list-api.mjs`, `contracts/openapi.json`.
- 적용 마이그레이션: PostgreSQL `encode(..., 'base64')` 출력의 개행 때문에 긴 cursor가 거절되는 현상을 발견했다. 이미 적용한 24300은 변경하지 않고 개행 제거를 추가한 후속 24400을 순서대로 적용했다.
- 실행 환경·도구 버전: Windows loopback Supabase, PostgreSQL 17.11, Node 24.19.0, pnpm 11.19.0, Next 16.4.0.

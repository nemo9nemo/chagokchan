# 탈퇴 재인증 증명의 서버·DB 발급 경계

2026-11-09 / W12-D1 / REQ-001/010·NFR-001·POL-ACCOUNT-002·POL-DELETE-002·POL-SEC-001·TC-REAUTH-PROOF-001

기존 로그인 JWT만으로 삭제 grant를 만들 수 없도록 서버의 목적/앱 origin별 HKDF 키와 HMAC 증명을 추가했다. DB의 별도 비로그인 발급 역할이 서명·현재 활성 사용자/세션·Google/account.delete·10분 기한·nonce를 검사하고, 같은 미소비 nonce는 한 grant만 반환한다. 키 미설정/비활성·변조·타 UUID/세션·만료·소비 후 재발급은 거절한다. 키 원문과 증명을 브라우저에 반환하지 않는다.

새 SQL 2개를 로컬에 적용해 55개가 됐다. 최초 적용에서 격리 Auth 역할 소유의 세션 함수에 실행 권한이 빠진 것을 실제 통합 검사로 찾았다. 실제 소유 역할에서 필요한 함수 실행만 부여하는 후속 SQL로 보완했고 적용된 SQL은 수정하지 않았다. 일반 API 역할은 발급 역할을 상속하거나 키를 읽고/쓰거나 grant를 직접 INSERT할 수 없다. 발급 역할도 RLS를 우회하거나 Auth/다른 제품 테이블에 접근하거나 grant를 소비/삭제할 수 없다.

전체 단위 235(신규 서명 4), DB 419(신규 카탈로그 13), 실제 로컬 Auth 세션 기반 통합 12가 통과했다. 검사 키·사용자·세션·제품 행을 정리하고 기존 상태를 보존했다. 실제 Google 제공자 결과는 합성했으므로 Google 통과는 0이다. [증거](../quality/reports/w12-d1-reauth-proof-check-2026-11-09.json).

W12-D1의 서버/DB 경계만 완료했다. 재인증 PKCE BFF·현재/새 UUID 확인·같은 계정의 세션 교체/이전 세션 폐기·탈퇴 API/UI는 W12-D2에서 연결한다. 배포 환경의 실제 검증 키 프로비저닝·Google/HTTPS 수락·독립 원장·worker/복원과 공개 출시는 별도다. Codex 직접 검토이며 독립 교차 리뷰라고 표시하지 않는다.

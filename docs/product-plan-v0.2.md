# 차곡찬 (Chagokchan) — 기획 v0.2

수정일: 2026-10-08 / 상태: 제품 방향·기술 정책 결정, 구현 전

## 제품 정의

**목표마다 셀프 칭찬과 지인에게 받은 칭찬을 개인·공유 칭찬판에 따로 모으는 앱.**

실제 출시를 목표로 한다. 포도는 교체 가능한 표현 테마이며 브랜드를 특정 과일에 묶지 않는다. 이후의 포도알·포도송이 예시는 해당 테마를 설명한다. 한글 출시명은 차곡찬으로 확정했다. 영문 표기 Chagokchan·개발 slug chagokchan은 [브랜드 기준](branding/brand-guide.md)을 따른다. 이전 후보는 [검토 기록](branding/name-candidates-2026-10-07.md)에 보존한다.

내 작은 실천을 직접 인정하고, 연결된 사람의 칭찬을 같은 목표 안에서 함께 돌아본다. 개인 기록과 받은 칭찬은 각각의 개수·포도송이·완성 기록으로 관리한다.

## 사용자와 확정한 요구

| 항목 | 확정 내용 |
| --- | --- |
| 중심 사용자 | 자기 실천과 성취를 기록하고 싶은 성인 개인. 한국 첫 가입 기준은 만 19세 이상 자기 확인 |
| 셀프 칭찬 | 내 개인 포도송이에 스스로 칭찬을 기록 |
| 계정 연결 | 다른 사용자와 연결하여 상대의 허용된 칭찬판에 칭찬 부여 |
| 개인·공유 구분 | 개인 포도알과 공유 포도알의 개수·기록을 별도 관리 |
| 목표별 생성 | 여러 목표를 만들고 목표마다 포도송이 생성 |
| 공유의 의미 | 내 목표의 공유 포도송이에 지인이 칭찬을 주는 방식 |
| 확장 가능성 | 포도 외 테마로 변경 가능. 그룹, 공동 목표, 보상, 위젯 등 확장 후보를 열어 둠. 테마 변경은 기록·집계·권한을 유지 |
| 진행 방식 | 기획과 시장조사를 중심으로 진행 |

개수 예시와 화면 구성은 검증할 기획 제안이다. 첫 출시는 모바일 웹/PWA, 로그인은 Google·이메일 인증번호로 정했다. 판별 권한·계정 연결은 [로그인·권한 문서](auth-and-permissions.md), 개발·배포는 [기술 아키텍처](technical-architecture.md)와 [배포 계획](deployment-and-git.md)을 기준으로 한다. 수익화는 아직 결정하지 않았다.

## 목표와 포도송이 구조

한 사람이 여러 목표를 갖는다. 각 목표에는 개인용 칭찬판이 있고, 원할 때 공유용 칭찬판을 추가한다. 칭찬판에서는 포도송이를 반복해서 완성하고 지난 포도송이를 보관한다.

| 구분 | 개인 포도송이 | 공유 포도송이 |
| --- | --- | --- |
| 쌓이는 것 | 내가 남긴 셀프 칭찬 | 허용된 지인이 내 목표에 남긴 칭찬 |
| 알을 붙이는 사람 | 목표 주인 | 해당 공유판에 칭찬할 권한이 있는 연결 사용자 |
| 기본 공개 범위 | 나만 보기 | 주인은 전체, 허용된 지인은 공유 정보·개수·본인이 보낸 칭찬만 보기 |
| 알별 기록 | 실천 내용·메모·날짜 | 주인에게는 보낸 사람·칭찬 내용·날짜, 지인에게는 자기 기록만 |
| 목표 개수 | 판별 설정 | 개인판과 독립적으로 설정 |
| 완성 기록 | 내 실천 포도송이 완성 | 받은 칭찬 포도송이 완성 |

**예시 — ‘독서 이어가기’ 목표:** 개인판 7/20알, 공유판 3/10알. 내가 오늘 독서를 기록하면 개인판만 8/20알이 된다. 지인이 칭찬을 주면 공유판만 4/10알이 된다. 두 개수를 합산해 목표 달성률로 표시하지 않는다.

포도송이를 다 채운 상태와 실제 목표를 달성한 상태도 구분한다. 받은 칭찬이 많이 쌓여도 실제 독서량이 늘어난 것으로 기록하지 않는다. ‘목표를 마쳤어요’는 목표 주인이 판단할 수 있게 한다.

## 핵심 사용 흐름

### 나를 칭찬하기

1. 계정을 만들거나 로그인한다.
2. ‘독서 이어가기’, ‘운동하기’, ‘내 작은 성취’ 등 목표를 만든다.
3. 개인 포도송이의 목표 개수를 정한다. 개발 기준은 기본 20알·범위 1~100알이며 10·20·30알은 화면 선택지로 사용할 수 있다. 새 설정은 다음 회차에 적용한다.
4. 실천한 순간 ‘나를 칭찬하기’를 눌러 개인 포도알을 채운다.
5. 짧은 메모나 자주 쓰는 칭찬 문구를 선택한다. 입력은 선택 사항으로 제안한다.
6. 완성한 포도송이와 기록을 모아 보고 다음 포도송이를 이어간다.

### 지인과 칭찬 주고받기

1. 내가 일회용 초대 링크·QR·코드를 만들고 지인에게 직접 전달한다.
2. 로그인한 지인이 연결 요청을 보내면 내가 확인하고 수락한다.
3. 목표 주인이 공유 포도송이를 만들고 공유용 제목·설명과 칭찬을 받을 사람을 선택한다.
4. 연결된 사람은 자신에게 허용된 공유판을 열고 ‘칭찬 보내기’를 누른다.
5. 공유 포도알과 보낸 사람의 기록이 남고, 목표 주인은 소식에서 확인한다.
6. 개인판의 포도알과 메모는 이 과정에서 변경되지 않는다.

초대 링크는 앱 안에서 생성하는 기능이다. 이번 기획 작업에서 실제 다른 사람에게 초대를 보내지는 않았다.

## 계정 연결과 판 권한

‘사람과 연결됨’과 ‘특정 목표에 칭찬할 수 있음’을 구분한다. 한 지인에게 운동 목표를 공유해도 다른 개인 목표가 함께 공개되지 않게 설계한다.

| 역할 | 할 수 있는 일 |
| --- | --- |
| 목표 주인 | 목표·판 생성, 내 기록 작성, 공유 대상 지정, 받은 칭찬 정리, 완료판 보관 |
| 칭찬할 수 있는 지인 | 허용된 공유판의 정보·개수와 자기 칭찬 보기, 칭찬 보내기, 자신이 보낸 칭찬 취소 |
| 보기만 하는 지인 — 확장 후보 | 허용된 공유판 보기 |
| 함께 관리하는 사람 — 확장 후보 | 공동 목표 도입 시 설정과 진행 관리 |

첫 버전은 주인이 허용한 지인의 칭찬이 바로 공유 포도알에 반영되는 방식이다. ‘주인 승인 후 반영’은 추후 판별 설정 후보로 남긴다. 지인에게 목표 제목·목표 개수·개인 기록 편집 권한은 주지 않는다. 다른 지인이 보낸 칭찬 본문과 개인판 정보도 자동으로 공개하지 않는다.

연결 해제·판 공유 해제는 이후 공유판 조회와 부여 권한을 끝낸다. 기존에 받은 칭찬은 기록으로 남기고 목표 주인이 숨기거나 개수에서 제외할 수 있다. 보낸 사람은 별도 보낸 칭찬 경로에서 자기 기록만 확인·취소할 수 있다. 차단과 알림 끄기도 연결 관리에 포함한다.

## 첫 버전 범위

| 기능 | 첫 버전에 필요한 동작 |
| --- | --- |
| 계정·동기화 | Google·이메일 인증번호 로그인, 프로필, 내 목표와 칭찬 기록의 기기 간 동기화·복원 |
| 목표 관리 | 여러 목표 생성, 제목·설명, 진행 중·완료·보관 관리 |
| 개인 포도송이 | 목표별 생성, 셀프 칭찬, 독립 개수, 문구·메모, 취소 |
| 공유 포도송이 | 목표별 선택 생성, 독립 개수, 초대된 지인의 칭찬 수신 |
| 사람 연결 | 일회용 코드·링크·QR, 요청·초대한 사람의 수락·거절, 연결 해제·차단 |
| 판별 권한 | 공유 대상을 선택하고 해제, 허용된 판만 조회·부여 |
| 칭찬 기록 | 보낸 사람·받는 사람·목표·날짜·종류를 기록, 알별 상세 보기 |
| 소식 | 받은 칭찬과 연결 요청을 확인, 읽음 상태 관리 |
| 완성판 모음 | 목표별·개인/공유별 완성 포도송이와 지난 기록 보관 |

핵심 검증은 ‘혼자 꾸준히 쓰는 가치’와 ‘다른 사람에게 칭찬을 받는 가치’ 두 가지다. 계정 연결과 공유 포도송이는 첫 버전의 핵심 범위로 포함한다.

## 화면 구성

기본 메뉴는 ‘내 목표 · 연결 · 소식’으로 제안한다. 지난 포도송이는 각 목표와 전체 기록 모음에서 확인한다.

| 화면 | 핵심 구성 |
| --- | --- |
| 내 목표 | 목표 카드, 개인 개수·공유 개수를 따로 표시, 새 목표 만들기 |
| 목표 만들기 | 이름, 개인판 개수, 공유판 선택 추가, 공유 대상 설정 |
| 목표 상세 | 목표 정보, ‘내 칭찬 / 받은 칭찬’ 전환, 해당 포도송이와 기록 |
| 내 칭찬 기록 | 셀프 칭찬 문구·메모, 날짜, 실수 취소 |
| 연결 | 연결된 사람, 요청, 초대, 상대가 나에게 허용한 목표 |
| 상대 목표 | 공유용 제목·설명·개수와 공유 포도송이, 내가 보낸 칭찬, 칭찬 보내기 |
| 칭찬 보내기 | 대상과 목표 확인, 칭찬 문구, 포도알 미리보기, 보내기 |
| 소식 | 받은 칭찬, 연결 요청, 해당 목표로 이동 |
| 지난 포도송이 | 목표와 개인/공유 구분, 완성 날짜, 알별 기록 |
| 목표·계정 설정 | 공유 대상, 알림, 목표 보관, 계정·복원 관리 |

개인·공유 구분은 색과 함께 제목·아이콘·개수로도 보여준다. 목표 주인의 화면과 지인의 화면에서는 가능한 행동에 맞춰 버튼을 보여준다. 설정과 개발 용어는 칭찬을 주고받는 화면에 넣지 않는다.

## 기록과 완성 규칙

- 기본 칭찬 1건은 해당 포도송이 1알이다. 하루 여러 번 기록할 수 있고 [요청 제한](auth-and-permissions.md)을 적용한다. 하루 한 번 실천판은 이후 별도 규칙으로 추가할 수 있다.
- 개인·공유 알은 서로 이동하거나 합산하지 않는다. 목표 카드에서도 각각의 진행 개수를 표시한다.
- 공유판에 칭찬을 보낼 때 대상 목표와 받을 사람을 확인한다. 중복 탭으로 같은 칭찬이 여러 알이 되지 않게 한다.
- 완성된 포도송이는 보관한다. 진행 중인 목표에 다음 칭찬이 오면 다음 포도송이를 만들어 남긴다.
- 거의 동시에 여러 칭찬이 도착해도 모두 기록하고, 각 칭찬은 한 포도송이에 한 번만 반영한다.
- 포도알을 취소하면 해당 포도송이 개수를 다시 계산한다. 목표 주인은 받은 칭찬을 숨기거나 제외할 수 있고, 보낸 사람의 작성자로 표시된 내용은 대신 고쳐 쓰지 않는다.
- 숨기기와 개수에서 제외하기는 서로 다른 동작이다. 단순히 화면에서 숨긴 기록은 개수를 유지하고, 제외한 기록은 개수에 반영하지 않는 기본안이다.
- 취소된 완료판은 개수가 목표 미만이 되면 완성 표시를 해제한다. 다음 포도송이가 이미 있으면 기존 기록을 옮기지 않는다.
- 목표 완료·보관 이후에는 새 칭찬 입력을 닫고, 재개했을 때 이어갈 수 있게 한다.

## 다양한 확장을 위한 구조

목표, 칭찬판, 포도송이 회차, 칭찬 기록, 사용자 연결, 판 참여 권한을 각각 관리하는 구조를 제안한다. 포도 그림은 칭찬 데이터를 보여주는 표현이다. 테마를 바꿔도 목표와 기록은 유지한다.

| 확장 방향 | 추가할 경험 | 지금 준비할 부분 |
| --- | --- | --- |
| 다양한 테마 | 꽃·별·과일·스티커판 | 기록과 판 그림을 독립적으로 관리 |
| 반복 습관·수치 목표 | 주간 실천, 독서 횟수·운동 시간 | 칭찬 기록과 실제 실천량 구분, 판별 기록 규칙 |
| 그룹·공동 목표 | 모임이 함께 채우는 판 | 목표 소유 주체와 참여자 역할을 확장할 구조 |
| 보상·배지 | 완성 보상, 누적 성취 배지 | 포도송이 완성과 목표 달성을 구분한 이벤트 |
| 위젯·리마인더 | 빠른 셀프 칭찬, 필요한 때 알림 | 공통 기록 동작, 사용자별 알림 설정 |
| 기록 공유·출력 | 이미지·월간 리포트·완성판 출력 | 범위별 조회와 개인/공유 권한 유지 |
| 사진·응원·댓글 | 더 풍부한 칭찬과 감사 표현 | 칭찬에 연결할 부가 기록과 공개 범위 |
| 외부 연동·AI 보조 | 실천 기록 가져오기, 칭찬 문구 추천 | 출처·작성 주체 구분, 연결 권한 관리 |

확장 구조와 기능 출시 순서는 별개로 관리한다. 첫 버전에서 모든 기능을 만들기보다, 기존 목표·포도송이·칭찬 기록을 유지하면서 새 기능을 붙일 수 있게 준비한다. 상세 원칙은 [기능 확장 설계](feature-expansion-design.md)에 정리했다.

## 시장조사 반영

국내 굿잡에는 칭찬보드와 공유 기능이 있고, HabitShare에는 친구별 습관 공개 설정이 있다. Finch는 연결된 친구에게 응원 메시지를 보내는 흐름을 제공한다. 따라서 계정 연결이나 지인 응원 자체를 독점적인 기능이라고 주장하지 않는다. [공식 자료와 추가 비교](market-research-2026-10-07.md)

우리 제품의 검증할 가설은 ‘목표별로 내가 인정한 실천과 지인이 인정한 순간을 각각 포도송이로 모으는 경험’이다.

## 검증할 시나리오

1. 한 사람이 서로 다른 목표 3개를 만들고 각 개인판에 쉽게 칭찬한다.
2. 두 사용자가 연결되고, 주인이 선택한 목표에만 공유 칭찬을 줄 수 있다.
3. 같은 목표에서 개인 7알·공유 3알이 서로 영향을 주지 않고 표시된다.
4. 지인이 칭찬을 보내면 수신자가 소식에서 목표와 보낸 사람을 바로 이해한다.
5. 공유 해제 후에는 해당 판을 조회하거나 새 칭찬을 보낼 수 없다.
6. 중복 전송·동시 전송·완성 직전 전송에서도 칭찬이 사라지거나 중복되지 않는다.
7. 테마를 바꾸거나 새 기기로 이동해도 개인·공유 기록과 완성판이 유지된다.

위 내용은 향후 시제품 검증 계획이다. 아직 앱을 구현하거나 실제 계정을 연결한 상태는 아니다.

## 기술 결정과 남은 기획

플랫폼·로그인·연결·권한·스택·보안·배포·Git 기준은 [문서 안내](README.md)에 정리했다. 남은 제품 검증은 다음과 같다.

- 목표 개수의 초기 선택지와 목표 기간 입력 UX
- 받은 칭찬 승인 옵션의 필요성
- 목표 완료·재개·보관과 포도송이 자동 이어가기의 세부 UX
- 앱 내 소식의 갱신 빈도와 추후 푸시 도입 시점
- 이름·분위기·시각 스타일, 수익화 방식

삭제·탈퇴·복구·계정 수명·날짜·상태·칭찬 정리는 [정책 JSON](../policies/app-policy.json), [제품 규칙](policies/product-rules.md), [생명주기](policies/data-lifecycle.md)에 개발 기준으로 구체화했다. 요구·화면·API·검증 산출물은 [실제 개발 절차](development/README.md)에서 관리한다. 성인 개인 범위와 [가입 정책](policies/audience-and-signup.md)은 확정했다. 운영 주체·예산·공개 정책은 출시 준비 입력이다. 사용 지표·확장 검토는 [추가 고려사항](additional-considerations.md)을 참고한다.

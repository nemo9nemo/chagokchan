# 차곡찬 1차 마무리·2차 출시·수익화·마케팅 실행안

기준일: 2026-10-19 / 근거: 사용자의 두 단계 진행 요청, 모바일 웹/PWA → Android → iOS 순서 선택, 무료 이용·광고 수익 질문.

이 문서는 실행 순서와 검증할 사업 가설이다. 서비스 개설·결제·광고 집행·스토어 제출·운영 배포를 완료했다는 뜻이 아니다. 구현 상태는 [진행표](development/backlog.md), 정책은 [제품 정책](../policies/app-policy.json)을 따른다. 가격·전환율·일정 목표는 제안이며 실제 수요와 비용으로 수정한다.

## 1차와 2차의 경계

| 구분 | 1차: 로그인 없이 로컬 사용 완성 | 2차: 실제 사용자 출시 |
| --- | --- | --- |
| 사용자 | 개발용 합성 A/B/C. 로그인 화면 없이 사용 | 한국 만 19세 이상 자기 확인을 한 실제 사용자 |
| 인증·권한 | 서버가 준비한 실제 로컬 Auth 세션, 동일 RPC/RLS | Google·이메일 OTP, 세션 갱신·로그아웃·재인증·가입 확인 |
| 실행 위치 | 앱과 DB 모두 loopback. 기존 fixture·데이터 보존 | 별도 staging/production, HTTPS, 실제 제공자 설정 |
| 완료 범위 | 목표·개인/공유 칭찬·연결·소식·휴지통·오류/재시도·화면, 로컬 DB/API/브라우저 검사 | 실제 로그인 여러 계정·실기기/PWA·복원·부하·보안·정책·운영 검증 후 공개 |
| 수익화 | 무료+광고·상품/가격 비교, 수요 조사 문안 | 무료 베타 후 광고 수용도·실제 수익 시험. 유료 상품은 선택 후보로 별도 검증 |

1차 무로그인은 공개 익명 서비스가 아니다. 로컬 가상 인증을 터널이나 공용 URL로 공개하지 않는다. 1차에 새 인증·결제·광고·분석 SDK를 넣지 않는다. 사용자 지정 기준은 [요구사항](requirements/mvp-requirements.md), [개발 정책](../policies/development-policy.json), [로컬 개발](development/local-development.md)에 함께 연결한다.

## 출시 순서와 통과 조건

| 순서 | 작업과 결과물 | 다음으로 넘어가는 조건 |
| --- | --- | --- |
| 1차 마무리 | W21: 실행 도구 고정, 완료 기록 동기화, 로컬 회귀와 범위를 한정한 브라우저 확인·Codex 직접 검토 | 관련 검사 통과. 미실행·알려진 제약을 명시. 전체 수락·실제 로그인/실기기는 2차로 구분 |
| 운영 준비 | W14: 운영 주체·지원 메일·도메인·월 예산·삭제 원장·공개 정책, staging/production 분리 | 실제 입력 확정, 접근권한과 비용 경보, 삭제/복원 절차 준비 |

| 비공개 베타 | W13/W15: 실제 로그인 성인 테스터 20~30명 제안, 개인 사용→선택 공유 | 여러 계정 권한·전체 필수 TC·iOS/Android 실기기·복원·성능 증거, 미해결 P0/P1 없음 |

| Android | W23: PWA 재사용 방식 검토, 서명 AAB·스토어 설명·Data safety·계정 삭제 URL·결제 방식 검증 | Play Console의 해당 계정 테스트/프로덕션 요건과 심사 통과 |
| iOS | W24: iOS에서 유용한 앱 경험·인증 대안·인앱구매/복원·접근성·심사 자료 | TestFlight와 App Review 통과. 단순 웹 포장만으로 승인된다고 가정하지 않음 |

공개 날짜는 운영 입력과 검증 결과로 정한다. 웹 베타는 목표 2~4주 관찰 주기를 제안하지만 개발 완료 예상이나 심사 기한의 보장이 아니다. 웹 공개 전에 테스터에게 로컬 앱 주소를 배포하지 않는다.

Android는 먼저 안정된 PWA를 재사용할 TWA/Bubblewrap을 검토한다. 알림·결제·외부 인증 복귀가 실제 기기에서 충족되는지 확인한 뒤 포장 방식을 확정한다. TWA는 동일 개발자의 웹과 앱 관계를 Digital Asset Links로 검증하는 방식이다. 앱 설치형 프로젝트는 아직 구현하지 않았다. [Chrome 공식 TWA 안내](https://developer.chrome.com/docs/android/trusted-web-activity)

Google Play 신규 개인 계정(2023-11-13 이후 생성)은 최소 12명이 14일 연속 참여한 비공개 테스트 후 프로덕션 접근을 신청해야 한다. 모집 목표를 20명 이상으로 잡아 이탈 여유를 둔다. 이 테스트가 앱 심사 승인을 보장하지는 않는다. 등록비는 US$25 일회다. [테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en) · [계정 등록](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en)

iOS의 Apple Developer Program은 연 US$99이며 지역별 결제액은 다를 수 있다. App Review 4.2는 재포장된 웹보다 충분한 앱 효용을 요구한다. 4.8은 Google 같은 제3자 로그인을 쓸 때 지정된 개인정보 보호 특성을 갖춘 동등한 로그인 대안을 요구하므로, iOS 단계에서 Sign in with Apple 도입 여부와 예외 해당 여부를 검토한다. 현재 Google/OTP 구현 완료로 기록하지 않는다. [등록 안내](https://developer.apple.com/programs/enroll/) · [심사 4.2·4.8](https://developer.apple.com/app-store/review/guidelines/)

계정을 만드는 앱은 Play 배포 전에 앱 내부와 외부 웹에서 계정 삭제를 요청할 수 있어야 한다. 기존 DB 삭제 RPC만으로 이 사용자 경로가 완성됐다고 보지 않는다. [Google 계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)

월 예산은 아직 미정이다. 처음에는 월 10만~15만원 이내 운영안을 비교하는 것을 제안하되, 위 별도 비용과 사용량을 넣어 확정한다. 이는 환율을 적용한 견적이나 결제 승인 금액이 아니다. 1차에는 유료 프로젝트를 개설하지 않는다. 비용 알림과 지출 차단은 다르므로 RPC 제한·사용량 관찰·비상 중단 절차를 유지한다.

서비스 생성 전에 운영 주체(개인/사업자), 지원 메일, 도메인, 월 상한, 독립 삭제 원장의 저장 위치·접근권한·암호화·만료, 개인정보/국외 이전·약관·유료 판매 의무를 확정한다. 법률·세무 검토가 필요한 항목은 운영 형태와 실제 공급자를 정한 후 확인하고, 미정 값을 공개 문서에 실제 연락처처럼 넣지 않는다.

## 수익 모델: 무료+광고 우선 검토와 유료 상품 비교

사용자의 추가 질문에 따라 **핵심 기능 무료 + 선택형 꾸미기 보상 광고**를 우선 검토안으로 둔다. [무료·광고 수익안](free-with-ads-plan.md)에 배치·플랫폼 차이·DAU/실제 노출/eCPM 산술과 미구현 범위를 정리했다. 무료 베타로 재방문을 확인한 뒤 Android에서 소규모 시험하는 순서를 권한다. 광고 도입이 확정된 것은 아니며 유료 구독을 출시 필수 조건으로 두지 않는다. 아래 판매·구독 가격은 이전 비교 가설로 유지한다.

핵심 메시지는 **“작은 실천을 스스로 인정하고, 선택한 사람의 응원을 따로 모은다.”**다. 첫 대상은 성인 개인이다. 가족/학급/조직 상품으로 동시에 확장하지 않는다.

| 상품 | 제안 | 도입 조건 |
| --- | --- | --- |
| 무료 핵심 | 현행 정책 범위의 목표·개인/공유 칭찬·기본 테마·연결·기록·권한·삭제 | 출시 기본값. 기존 20개 목표·권한 등 정책 상한은 이 제안만으로 바꾸지 않음 |
| 꾸미기 팩 | 새 테마/스티커 묶음 2,900~4,900원 일회 구매 가설 | 원본 기록·개수·권한 불변, 실제 추가 자산·구매 복원·환불 경계 구현 후 판매 |
| 차곡찬 Plus | 월 3,900원 / 연 29,900원 시험안. 추가 테마, 회고 보기 등 지속 가치 후보 | 반복 사용과 구매 의사 확인, 실제 차별 기능·구독 해지/복원·결제 상태 검사 후 도입 |

현재 테마 전환은 탭 메모리에서만 동작하며, 추가 테마 팩·회고·결제·구매 복원·구독 권한·광고·보상 이용권은 미구현이다. 동기화·기록 접근·삭제·차단 같은 기본 안전 기능은 유료 전환이나 광고 시청 조건으로 막지 않는다. 상품·광고 보상이 집계 변화나 개인/공유 합산을 만들지 않는다. 평생 클라우드 이용권은 장기 운영비가 검증되기 전 판매하지 않는다.

App Store 구독은 지속적인 가치를 제공해야 한다. Play의 디지털 기능/상품 결제는 원칙적으로 Play 결제 시스템을 쓰며 예외·국가 프로그램은 실제 배포 시 다시 확인한다. 웹 PG가 붙었다고 스토어 앱에서 같은 결제 동선을 바로 쓸 수 있다고 가정하지 않는다. [Apple 구독 3.1.2](https://developer.apple.com/app-store/review/guidelines/) · [Google 결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)

### 유료 상품의 비교용 매출 가설과 손익 계산

아래는 MAU와 구매 전환율을 가정한 계산이며 예측 매출이 아니다. 월 3,900원 상품만 사용하고 연 결제와 일회 구매를 섞지 않는다.

| 월 활성 사용자 | 월 결제자 비율 가정 | 결제자 | 월 총매출 | 가상 수수료 15% 차감 후 |
| --- | --- | --- | --- | --- |
| 1,000명 | 3% | 30명 | 117,000원 | 99,450원 |
| 5,000명 | 3% | 150명 | 585,000원 | 497,250원 |
| 10,000명 | 3% | 300명 | 1,170,000원 | 994,500원 |

세금·환불·광고비·인건비·운영비를 빼기 전 금액이다. 15%는 민감도 계산 가정이며 모든 판매 경로의 실제 요율이 아니다. Apple Small Business Program은 자격·신청 조건에 따라 15% 수수료가 적용되는 예다. [Apple 프로그램](https://developer.apple.com/app-store/small-business-program/)

고정 운영비를 가상으로 월 150,000원, 변동비를 위 15%만으로 놓으면 1인 월 기여액은 3,315원이고 최소 46명 결제자가 필요하다. 전환율 3%를 그대로 가정하면 MAU 약 1,534명이다. 실제 세금·환불·추가 변동비를 넣으면 더 필요하다. 연 29,900원은 1인당 월 환산 약 2,492원이므로 월 상품 계산을 그대로 대입하지 않는다.

수요 검증 순서: 반복 사용한 성인 10명 인터뷰 → 가격/꾸미기/회고 선택 질문 → 20명 이상에게 가격을 명시한 구매 의향 확인 → 실제 상품 구현 후 소액 판매. 결제 버튼이 작동하는 것처럼 꾸미거나 판매 전 비용을 받지 않는다. 인터뷰 동의는 칭찬 본문이나 지인 정보의 광고 이용 동의가 아니다.

## 마케팅: 좁은 대상·짧은 데모·반복 사용부터

초기 대상 가설은 **자기계발 기록을 하고 싶지만 강한 연속 기록·순위 경쟁은 부담스러운 성인**이다. 효능이나 치료 효과를 주장하지 않는다. 연령 확인은 현행 만 19세 이상 자기 확인이며 신분증 검증으로 광고하지 않는다.

| 채널 | 실행안 | 판단 지표 |
| --- | --- | --- |
| Instagram Reels/짧은 영상 | 주 3회, 10~20초 실제 기능 데모. 오늘 한 일 하나→셀프 칭찬→따로 쌓이는 받은 칭찬 | 방문 대비 첫 칭찬, 저장/재방문. 단순 조회수만으로 확대하지 않음 |
| Threads·성인 습관/독서 커뮤니티 | 주 2회 제작 과정·사용 예시, 허용된 곳에서 베타 모집 | 적합한 성인 테스터와 피드백. 무단 홍보·대량 메시지 없음 |
| 네이버 블로그·검색용 공개 안내 | 주 1회 “나를 칭찬하는 기록 예시”, “친구 응원을 부담 없이 받는 법” | 공개 안내 방문→베타/가입 전환. 개인판·초대·사용자 기록은 검색에 노출하지 않음 |
| 지인 추천 | 2차에서 한 목표만 명시적으로 허용해 초대하는 핵심 흐름 안내 | 초대 수락과 실제 공유판 첫 칭찬을 별도로 관찰. 사람 연결=판 권한으로 표현하지 않음 |

채널 선택과 빈도는 실험안이며 성과 보장이 아니다. 공개 검색 콘텐츠는 실제 도움이 되는 원문과 명확한 제목을 사용한다. 검색 등록이나 상위 노출은 보장되지 않는다. [Google Search Essentials](https://developers.google.com/search/docs/essentials)

### 4주 실행 묶음

| 주차 | 결과물 | 실행 시점 |
| --- | --- | --- |
| 준비 1주 | 한 문장 소개·가상 데이터 데모 3개·테스터 안내·질문지·공개 안내 문안 | 1차에서 로컬 파일 준비 가능. 아직 게시하지 않음 |
| 준비 2주 | 성인 사용 상황 인터뷰 10명 목표·랜딩/지원/삭제 안내 구현·측정 정의 | 외부 연락은 사용자가 수행하거나 별도 명시 승인. 실서비스 연결은 2차 |
| 베타 1주 | 로그인한 성인 20~30명 시작·첫 기록 성공 관찰·상위 불편 3개 수정 | W12/W13와 개인정보 처리 준비 뒤 |
| 베타 2주 | 7일 재방문·자발 공유·구매 의향 확인·Android 테스터 확보 | 유지율과 결함 근거로 공개/추가 개선 결정 |

사용자 모집을 위한 마케팅 광고비의 기본 제안은 0원이다. 앱 내부 광고 수익과는 구분한다. 이후 최소 50명의 첫 기록 완료자, 재방문 관찰, 실제 결제 경로 준비가 확보되면 총 5만~10만원 이내의 별도 승인된 소규모 광고를 검토한다. 이는 현재 집행 승인이나 업계 평균 기준이 아니다. 채널별 방문→첫 기록→유지→결제를 확인하고, 유지되지 않으면 광고 확대보다 첫 사용 문제를 고친다.

### 측정 정의와 개인정보 경계

계측은 아직 미구현이다. 1차에는 외부 분석 도구로 전송하지 않는다. 2차에서는 수집 목적·보관·동의/적법 근거와 비필수 분석의 비활성 경로를 정한 뒤 최소 이벤트만 구현한다. 초대 fragment·코드·쿠키·이메일·칭찬 본문·태그 내용·목표 이름·지인 정보는 분석 payload와 URL 수집에서 제외한다.

| 지표 | 계산 정의 | 사용 |
| --- | --- | --- |
| 첫 기록 활성화 | 가입 후 24시간 이내 새 셀프 칭찬 저장 성공한 사용자 / 해당 가입 코호트 | replay와 실패는 새 저장으로 세지 않음 |
| D7 유지율 | 첫 기록일의 한국 날짜 +7일에 돌아와 새 셀프 칭찬을 저장한 사용자 / 첫 기록일 코호트 | 아직 7일 안 된 코호트 제외. 유의미한 표본 전 결론 보류 |
| 주간 반복 기록 | 최근 7개 한국 날짜 중 3일 이상 새 셀프 칭찬 저장한 사용자 수 | 마케팅 관찰 지표이며 목표 달성량이 아님 |
| 공유 시작 | 명시 grant 뒤 첫 peer 칭찬을 받은 목표 주인 수 | 개인 칭찬과 합산하지 않음. 초대 수락만으로 공유 성공으로 세지 않음 |
| 유료 전환 | 해당 월 유효 유료 이용자 / 해당 월 활성 사용자 | 체험·환불·월/연·채널을 구분 |
| 획득 비용 | 채널 광고비 / 그 채널에서 온 첫 결제자 | 표본·기여 기간을 함께 기록. 장기 잔존을 가정해 광고를 늘리지 않음 |

유지율 목표를 처음에는 D7 20%로 시험해 볼 수 있으나 서비스 자체의 가설일 뿐 검증된 업계 기준이 아니다. 실제 표본 수·취소/환불·사용자 피드백을 함께 본다.

실제 게시할 문구와 테스터 문안은 [마케팅 준비물](marketing/launch-kit.md)에 둔다. 발송·게시·결제·스토어 제출은 수행하지 않았다.

# 성인 사용자 범위와 가입 정책

버전: 0.2.0 / 상태: 사용자 범위 확정·개발 기준 / 결정일: 2026-10-07

사용자는 첫 출시를 **성인 개인 사용자 중심**으로 확정했다. 구체적인 가입 연령과 확인 방법은 그 범위를 구현하기 위한 개발 선택이다. 기준 값은 [정책 JSON](../../policies/app-policy.json), 근거와 변경 영향은 [ADR-0002](../decisions/ADR-0002-adult-personal-audience.md)에 기록한다.

## POL-AUDIENCE-001 — 첫 출시 대상과 가입

| 항목 | 개발 기준 |
| --- | --- |
| 대표 사용자 | 자신의 작은 실천과 성취를 기록하는 성인 개인 |
| 첫 경험 | 목표 하나 만들기 → 셀프 칭찬 한 번. 지인 연결은 선택 |
| 지인 사용 | 각자 성인 개인 계정으로 연결하고 주인이 선택한 공유판에 칭찬 |
| 한국 가입 기준 | 가입 시점에 만 19세 이상 |
| 확인 방법 | 사용자가 직접 선택하는 성인 확인. 기본 선택 없음 |
| 확인 문구 | “저는 만 19세 이상입니다.” |
| 저장 항목 | 서버 UTC adult_confirmed_at·registration_policy_version |
| 수집하지 않는 확인 자료 | 생년월일·주민등록번호·신분증·전화 본인확인 정보 |
| 초기 역할 | 개인 소유자·목표별 contributor |
| 확장 후보 | 미성년자·보호자·가족·교실·조직 계정. 도입 시 별도 요구·동의·권한 설계 |

한국 첫 출시의 19세 기준은 [민법 제4조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1026056227)의 성년 기준을 참고해 선택했다. 자기 확인은 사용자의 선언을 기록하는 방법이며 실제 나이·신원을 검증한 결과로 표시하지 않는다. 국가를 확장하거나 확인 방법을 강화할 때는 정책·화면·수집·보관·외부 처리 범위를 다시 정한다.

성인 확인은 개인정보 처리 동의·이용약관 동의와 다른 목적이다. 실제 공개 문서와 필요한 동의 구성은 운영 주체·제공자 설정을 확정해 출시 전에 작성한다. 성인 확인만으로 모든 동의를 받았다고 처리하지 않는다.

## 가입과 로그인 흐름

1. 로그인 화면에 성인 개인 서비스임을 안내하고 Google·이메일 OTP로 인증한다.
2. 서버가 검증된 Auth UUID와 현재 세션을 확인한다. 이미 active인 앱 계정은 기존 목적지로 이동한다.
3. Auth 인증은 되었으나 app_users와 진행 중 정리 표시가 없으면 signup_required를 반환하고 /signup으로 이동한다. 정리 표시가 있으면 deleting 안내를 적용한다. 새 목표·초대·연결·칭찬 API는 아직 사용할 수 없다.
4. 가입 화면에서 성인 확인과 현재 정책 버전을 제출한다. 미선택·false·누락은 거절한다. 이전 정책 버전은 최신 안내를 다시 확인하도록 처리한다.
5. 서버와 bootstrap RPC가 현재 사용자·세션·정책 버전을 검증하고 app_users·profiles 및 확인 기록을 한 트랜잭션에 생성한다.
6. 첫 목표 화면 또는 서버에 보관한 허용된 초대 목적지로 이동한다. 초대 소비·사람 연결·판 권한 부여는 별도 행동이다.

기존 계정 로그인과 bootstrap 재시도는 최초 확인 시각·버전을 덮어쓰지 않는다. 새 가입의 버전 비교는 최초 생성에 적용하며 기존 active 계정의 재시도는 원래 기록을 반환한다. 정책 버전 변경이 기존 사용자의 자동 재동의를 뜻하지 않는다. deleting 계정은 가입 경로로 재활성화하지 않는다.

새 사용자가 확인을 취소하면 앱 계정을 만들지 않고 현재 인증 세션과 임시 초대를 정리한다. 가입 미완료 Auth 사용자는 생성 후 24시간 내 정리를 운영 목표로 한다. 정리 작업과 bootstrap은 같은 사용자 잠금·진행 중 정리 표시를 사용해 경합을 막고, 이미 앱 계정이 생성되었으면 정리하지 않는다. 실제 정리 작업은 W10에서, 가입·인증 연동은 W12/W13에서 구현·검증한다.

## 데이터와 공개 범위

확인 시각·버전은 app_users의 필수 필드이며 본인 계정 응답에서만 제공한다. 공개 프로필·공유판·보낸함·소식에는 포함하지 않는다. 확인 값을 별도 사용자 검색·연령 추정·추천 데이터로 사용하지 않는다. 계정 정리 시 함께 파기하고 백업·원장 처리는 [생명주기](data-lifecycle.md)를 따른다.

ERD에는 보호자·아동 관계를 미리 추가하지 않는다. 후속 확장은 기존 개인 계정·목표 소유·판 권한을 보존하면서 새 정책과 데이터 모델을 추가한다.

검증: [TC-AUTH-004·TC-AUDIENCE-001](../quality/test-cases.json). 현재는 설계·검증 계획이며 실제 가입 제한이나 연령 확인 기능이 구현된 상태는 아니다.

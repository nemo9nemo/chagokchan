# 권한과 응답 필드 정책

버전: 0.2.0 / 상태: MVP 개발 기준 / 기준일: 2026-10-07

## POL-ACCESS-001 — 읽기 경계

활성 앱 계정·현재 Auth 세션을 모든 보호 조회에 적용한다. RLS와 서버 응답 projection을 함께 사용한다. 일반 테이블의 직접 DML은 회수하고 업무 RPC를 사용한다. [기존 권한표](../auth-and-permissions.md)

| 경로·역할 | 허용 응답 | 금지 응답 |
| --- | --- | --- |
| 내 계정 | 본인 UUID·공개 프로필·표시 시간대·계정 상태·최초 성인 확인 시각/버전 | 토큰·원시 Auth identity·다른 사용자 이메일 |
| 내 목표·판 | 본인 목표 ID·제목·설명·상태·revision, 개인/공유판 설정·회차·본인/받은 기록 | 다른 사용자의 개인 원본 |
| 지인의 공유판 | shared board ID·공유 제목/설명·최소 주인 프로필·목표 입력 상태·공유 회차·전체 공유 개수·기능 가능 여부 | 개인 goal ID·개인 제목/설명·개인 개수·다른 contributor 목록 |
| 공유판 칭찬: 주인 | 받은 칭찬 ID·본문·출처·회차·시각·작성자 표시·취소/숨김/제외 상태 | 작성자의 이메일·계정 설정 |
| 공유판 칭찬: 지인 | 본인 칭찬 ID·본문·회차·시각·취소 상태 | 다른 지인의 칭찬 본문·작성자 정보·수신자의 숨김/제외 상태 |
| 보낸함 | 본인 peer 칭찬 ID·본문·기록 시각·취소 상태·cancel 가능 여부 | 상대의 현재 목표·개수·상대의 정리 상태·새 개인 프로필 |
| 판 권한 관리 | 주인에게 멤버 UUID·최소 프로필·권한 상태·회차 | 지인에게 전체 멤버 목록 |
| 연결 목록 | 당사자 connection ID·상태·현재 허용된 최소 프로필 | 전체 사용자 검색·이메일 검색 |
| 초대 미리보기 | 유효 비밀 검증 후 닉네임·만료 시각 | 원시 profiles SELECT·목표·판 정보·초대 해시 |
| 내 소식 | type·시각·읽음·허용된 대상 종류/ID | 복사된 본문·다른 수신자 소식·초대 비밀 |
| 내 휴지통 | 본인 삭제 목표 ID·제목·revision·삭제 시각·기한 | 지인 조회·칭찬 입력 |
| 운영 보조 | API의 최소 결과 | request_receipts·reauth_grants·rate_usage·audit 원시 행 |

최소 프로필은 user_id·nickname·허용된 avatar_key만 의미한다. 성인 확인 시각·정책 버전은 공개 프로필·공유판·보낸함·소식에서 제공하지 않는다. 초대 미리보기는 nickname만으로 제한한다. 관계 종료·작성자 삭제로 프로필을 읽을 수 없으면 대체 표시를 사용하고 추가 정보를 조회하지 않는다.

공유 조회를 위해 goals 원본을 통째로 JOIN해 반환하지 않는다. 필요한 목표 상태만 권한 검사를 통과한 projection으로 반환한다. 소식 원문 이동에도 현재 권한·대상 삭제 상태를 다시 검사한다.

## POL-API-001 — 요청·결과

API의 상세 기준은 [계약 문서](../contracts/api-contract.md)와 [OpenAPI](../../contracts/openapi.json)다. 클라이언트에서 owner_id·actor_id·recipient_id·count·bunch_id를 변경 입력으로 받지 않는다.

접근할 수 없는 객체와 존재하지 않는 객체는 같은 404다. 이미 조회 권한이 있는 객체에서 허용되지 않는 작업은 403이다. 오류는 안정된 code·안전한 message·request_id·필요한 retry_after_seconds만 포함한다.

보낸함과 취소 결과는 상대 판의 최신 진행 개수를 반환하지 않는다. 칭찬 생성은 ID·회차 ID만 반환하고 현재 화면에서 권한을 적용해 다시 조회한다. 오래된 성공 응답의 개수로 최신 상태를 덮어쓰지 않는다.

## POL-SEC-001 — 강제 위치

서버는 JSON·Origin·CSRF·Fetch Metadata·크기·입력·IP/사용자 요청 제한을 확인한다. DB RPC는 실제 사용자·세션·목표 상태·연결·차단·판 권한·중복·필수 사용자별 제한을 다시 검사한다.

권한 해제·차단·탈퇴 접근 중단과 칭찬 쓰기는 같은 잠금 순서를 따른다. 해제 커밋 후 시작한 새 요청은 거절하고 앞서 완료한 기록은 생명주기 정책대로 처리한다. 일반 경로에 service role을 사용하지 않는다.

사용자 HTML·RSC·API·로그인·초대 응답에는 private, no-store를 적용한다. PWA는 공개 정적 파일만 캐시하고 로그아웃·계정 전환 때 조회 캐시와 임시 초대를 지운다.

권한·세션·RLS·직접 RPC·응답 필드·중복·동시성·캐시 검증을 [테스트 계획](../quality/verification-plan.md)에 연결한다.

# 제품 동작 정책

버전: 0.2.0 / 상태: MVP 개발 기준 / 기준일: 2026-10-07

개수·시간·상한의 기준은 [app-policy.json](../../policies/app-policy.json)이다. 아래 규칙은 기존 요구와 기술 결정을 구체화한 개발 기준이다. 사용자의 명시 요구와 이번에 선택한 구현 규칙은 [ADR](../decisions/ADR-0001-development-baseline.md)에 구분했다. 첫 출시는 성인 개인 사용자 중심으로 확정했다. 가입 기준과 확인 방법은 [성인 가입 정책](audience-and-signup.md)을 따른다.

## POL-GOAL-001 — 소유와 판

목표의 소유자는 한 사용자다. 목표 생성 트랜잭션에서 개인판을 반드시 하나 만들고 공유판은 명시적으로 선택할 때 하나 만든다. 기록이 생긴 판의 종류와 소유자는 바꾸지 않는다.

공유판에는 별도의 제목·설명을 입력한다. 개인 원본을 자동 공개하지 않는다. 사람 연결 수락과 목표별 판 권한 부여는 각각의 작업이다.

## POL-GOAL-002 — 목표 상태

| 현재 상태 | 요청 | 다음 상태 | 기록·권한 처리 |
| --- | --- | --- | --- |
| active | complete | completed | 신규 칭찬 종료, 현재 회차·기록·기존 판 권한 유지 |
| active 또는 completed | archive | archived | 신규 칭찬 종료, 본인과 유효 권한 지인의 조회 가능 |
| completed 또는 archived | resume | active | 현재 회차 이어가기, completed_at·archived_at 비움 |
| active·completed·archived | delete | deleted | 일반 조회·보낸함에서 대상 기록 제외, 판 권한 회수, 휴지통 기한 설정 |
| deleted, 복구 기한 전 | restore | archived | 주인만 복구, 기록 유지, 과거 판 권한 자동 복구 없음 |

complete는 active에서만 가능하고, 완료·보관·재개 요청을 같은 상태에 반복하면 추가 부작용 없이 현재 상태를 반환한다. 그 밖의 잘못된 전이는 409다. deleted의 일반 경로는 404다.

실제 변경에는 expected_revision 검증과 revision 증가를 적용한다. 완료·보관·재개의 이미 충족된 반복 명령은 변경 없이 현재 결과를 반환한다. 복구 시 deleted_at·purge_after를 NULL로 비운다.

목표 완료는 실제 목표를 마쳤다는 주인의 선택이다. 포도송이 완성과 별개다. complete·archive로 미완성 포도송이를 강제로 완성하지 않는다. 상태·내용 변경은 revision으로 충돌을 검사한다.

## POL-CYCLE-001 — 회차·집계

한 칭찬은 1알이다. 개인·공유판의 집계를 합치거나 서로 이동하지 않는다. 유효 개수는 cancelled_at과 excluded_at이 모두 NULL인 칭찬 수다. hidden_at과 작성자 삭제는 개수에 영향을 주지 않는다.

초기값은 판별 20알, 입력 범위는 1~100알이다. 설정 변경은 boards.next_target_count에 저장하고 기존 bunches.target_count를 바꾸지 않는다. 회차 생성 때 설정을 복사한다.

판 생성 시 current_bunch_id는 NULL이다. 첫 칭찬에 1회차를 만들고, 현재 회차가 완성된 뒤의 새 칭찬은 다음 회차를 만든다. 완성은 valid_count = target_count일 때만 표시하며 completed_at은 현재 완성 상태의 시각이다. 취소·제외로 목표 미만이 되면 incomplete, completed_at=NULL이다.

과거 회차 취소로 현재 회차 포인터·다른 기록을 옮기지 않는다. 한 회차의 개수는 목표 개수를 넘지 않는다. 부여·집계·완성·소식·요청 결과는 한 트랜잭션이다. 회차 완성 소식은 회차당 한 번만 만든다.

## POL-PRAISE-001 — 부여

개인판은 주인만, 공유판은 유효한 연결·차단 없음·해당 판 권한을 가진 다른 사용자만 칭찬을 부여한다. 목표는 active여야 한다. 작성자·수신자·회차·종류·개수는 서버/DB에서 결정한다.

서버 시각 recorded_at을 사용하고 개인 메모·공유 칭찬 본문은 선택 입력이다. HTML·첨부·외부 이미지는 첫 버전에 제공하지 않는다. 새로운 요청은 작성자 계정과 실제 세션이 활성 상태여야 한다.

## POL-PRAISE-002 — 수정·취소·숨김·제외

| 동작 | 수행자 | 허용 조건 | 본문 | 집계 |
| --- | --- | --- | --- | --- |
| 개인 메모·실천일 수정 | 주인=작성자 | self, 미취소, 목표 미삭제 | 변경 가능 | 유지 |
| 공유 문구 수정 | 첫 버전 미제공 | 취소 후 권한이 있을 때 새 칭찬 가능 | 변경 불가 | 유지 |
| 취소 | 작성자 | 본인 기록, 목표 미삭제 | 취소 트랜잭션에서 제거 | 해당 회차에서 감소 |
| 숨기기·숨김 해제 | 수신자 | peer, 미취소, 목표 미삭제 | 주인 기본 목록에서 숨김/복원 | 유지 |
| 개수 제외 | 수신자 | peer, 미취소, 목표 미삭제 | 기록 상태와 함께 유지 | 해당 회차에서 감소 |

연결·차단·판 권한이 끝난 작성자도 보낸함 경로로 자기 기록을 취소할 수 있다. 상대의 목표·현재 개수는 제공하지 않는다. 취소는 되돌리지 않고 취소 후 본문·실천일은 응답하지 않는다. 개수 제외의 복구는 첫 버전에 제공하지 않는다.

다른 사람이 쓴 문구를 수신자가 편집할 수 없다. 숨김·제외 상태는 수신자의 정리 정보이므로 보낸함에 공개하지 않는다. 숨김과 제외를 함께 적용할 수 있고 각각 집계 규칙을 지킨다. 같은 정리 동작의 반복 요청은 추가 감소·소식을 만들지 않는다.

## POL-TIME-001 — 날짜와 하루 제한

저장 시각은 UTC, 표시 기본 시간대는 Asia/Seoul이며 허용된 IANA 시간대 설정을 사용한다. 하루 제한 버킷은 서버 UTC 자정 기준이다. 사용자 시간대 변경·실천일 입력으로 제한 창을 바꾸지 않는다. 사용자에게 재시도 가능 시각을 표시한다.

self의 occurred_on은 표시 시간대 기준 오늘부터 과거 365일까지 선택 입력한다. 미래 날짜는 거절한다. 수정 시에도 현재 정책 범위를 적용한다. peer에는 실천일 입력을 받지 않고 recorded_at을 표시한다. 과거 실천일로 과거 회차를 지정할 수 없다.

## POL-CONNECT-001 — 초대·요청

24시간·1회용 링크/코드로 요청을 만들고 초대한 사람이 48시간 안에 수락한다. 코드와 링크는 같은 초대 한 건을 소비한다. GET·링크 미리보기는 초대를 소비하지 않는다.

유효 비밀 검증은 POST지만 상태를 바꾸지 않는 미리보기다. nickname과 유효 기간 같은 최소 정보만 반환한다. 명시적인 요청 생성에서 redeemed 상태·요청 행·소식을 함께 기록한다.

한 정규화 사용자 쌍에는 대기 요청 한 건만 허용한다. 반대 방향의 새 요청, 이미 연결된 관계는 409이며 사용하려던 별도 초대를 소비하지 않는다. 같은 요청 키 재시도는 기존 요청을 반환한다. 자기 초대·차단·만료·폐기·사용한 비밀은 동일한 접근 불가 결과로 처리한다.

| 대기 요청 동작 | 수행자 | 결과 |
| --- | --- | --- |
| accept | 초대한 사람 | active 연결, generation 증가, 판 권한은 별도 |
| reject | 초대한 사람 | rejected, 초대는 이미 소비된 상태 유지 |
| cancel | 요청자 | cancelled, 초대는 이미 소비된 상태 유지 |
| expire | 서버 | expires_at 경과 시 expired, 수락 불가 |

중복 수락은 generation을 다시 증가시키거나 해제된 연결을 다시 활성화하지 않는다. 거절·철회·만료 뒤에는 새 초대로 요청한다.

## POL-CONNECT-002 — 해제·차단·재연결

연결 해제는 inactive로 바꾸고 해당 연결의 board_members를 revoked로 바꾼다. 차단은 해당 연결과 대기 요청을 종료하고 이후 조회·새 칭찬을 거절한다. 초대 비밀은 특정 수신자를 지정하지 않으므로 전체 발급 목록을 지우는 대신 차단된 쌍의 사용을 거절한다.

차단 해제만으로 연결·판 권한을 복구하지 않는다. 재연결할 때 generation을 증가시키고 주인이 판 권한을 다시 부여한다. 권한 유효 조건은 현재 connection_id·generation·active·양방향 차단 없음이다.

## POL-LIMIT-001 — 상한과 입력

활성 목표 20개, 보관 중인 목표를 포함한 잔존 목표 100개, 활성 연결 200명, 공유판 contributor 50명으로 시작한다. 삭제 대기 목표도 잔존 수에 포함한다. 초대 활성 5개와 일일 20개 발급 제한은 기존 인증 정책을 따른다.

목표·공유 제목 80자, 설명·칭찬 1,000자, 닉네임 1~20자로 제한한다. 길이는 Unicode 코드 포인트 기준으로 서버와 DB를 맞춘다. 제목·닉네임은 NFC 정규화와 앞뒤 공백 제거 후 검증하고, 본문은 줄바꿈 정규화·NFC·빈 문자열의 NULL 처리를 일관되게 적용한다.

기타 JSON 크기·페이지·OTP·초대·칭찬 제한은 정책 JSON을 따른다. 상한 검사는 서버뿐 아니라 관련 업무 RPC에서도 동시 요청에 안전하게 적용한다. 같은 성공 요청의 재시도는 업무 제한을 추가 소비하지 않는다.

칭찬 일일 한도는 부여에 적용한다. 수정·취소·숨김·제외는 별도 분당 60회 제한으로 보호하며 부여 한도를 다 썼어도 정리할 수 있다. 초기 프로필은 '새로운 포도', 아바타 허용 키는 grape·leaf·star다. 닉네임은 유일 식별자나 계정 복구 근거로 사용하지 않는다.

# 실제 출시 사례와 차곡찬의 공개 순서

기준일: 2026-10-19 / 작업: W22-C / 출처: 사용자 “앱 출시가 목표, 부수익은 서브”

성공 기준은 실제 사용자가 안전하게 가입해 첫 목표와 칭찬을 기록하고 다시 사용할 수 있는 앱을 공개하는 것이다. 광고·유료 테마·구독은 첫 출시의 필수 조건에서 제외한다. 매출 가설을 완성하기 위해 출시를 늦추지 않는다. 플랫폼 순서는 모바일 웹/PWA → Android → iOS를 유지한다.

## 개발자가 직접 설명한 사례

| 사례·원문 | 실제 진행 | 차곡찬에 적용할 판단 |
| --- | --- | --- |
| [Daily by Buffer 개발 회고](https://buffer.com/resources/how-we-built-daily-by-buffer-in-two-weeks/), 2014 | 콘텐츠를 추가/넘기는 작은 첫 버전에서 출발했다. 기존 인증·API 코드를 재사용하고 내부와 기존 테스터 그룹에 배포했다. 초기 검증에 불필요한 확장 기능을 제거했다. | 목표 생성 → 셀프 칭찬 저장 → 재방문을 먼저 완성한다. 기존 RPC·RLS를 재사용하고 광고·상품 개발을 출시 선행 조건으로 두지 않는다. |
| [ABGT250 개발자 회고](https://buffer.com/resources/tiny-side-project-official-festival-app-10k-users/), 2017 | TestFlight 베타 초대 페이지를 만들고 해당 행사 팬 커뮤니티에 알려 반응을 얻었다. Android 요구와 운영 주체 협의·개인정보 우려를 확인하며 앱을 발전시켰다. | 성인 기록 앱을 실제 사용할 소규모 집단에서 피드백을 받는다. 지인 공유는 선택으로 두고 권한·지원 경로를 준비한다. 커뮤니티 게시·초대 발송은 아직 수행하지 않았다. |
| [Linear 초기 개발 회고](https://linear.app/now/building-at-the-early-stage), 2021 | 초기 기능을 내부와 비공개 베타에 먼저 전달하고 바로 피드백을 받아 수정했다. 프로젝트를 작게 나누고 여러 차례 공개하며 개선했다. | 웹/PWA 공개, Android 비공개 테스트, Android 공개, iOS를 각각의 검증 가능한 출시로 본다. 변경마다 테스트·직접 리뷰·PR·필수 CI·병합으로 완성한다. |

위는 당사자의 과거 경험이며 현재 스토어 규정이나 차곡찬의 성공률·개발 기간을 보장하지 않는다. B2B 도구와 행사 앱은 차곡찬과 대상·사용 빈도가 다르다. 여기서 취하는 것은 작은 범위·실사용 피드백·단계적 공개라는 실행 방식이다. 아래 인원·기간은 차곡찬의 제안이다.

## 차곡찬 출시 경로

1. **코드 준비:** 실제 세션 해석 → Google/OTP·가입·갱신/로그아웃 → 재인증·탈퇴 → 첫 사용/초대 복귀 → 전체 수락·기기·복원·부하를 진행한다. 로컬에서는 로그인 화면 없이 기존 A/B/C로 계속 개발한다.
2. **비공개 모바일 웹/PWA:** 운영 입력·실제 로그인·지원/개인정보·삭제 경로 준비 뒤 성인 5~10명에게 첫 기록 과정과 불편을 관찰하는 작은 시험을 제안한다. 이후 20~30명으로 넓혀 7일 재방문을 확인한다. 이 숫자는 법정·스토어 필수 인원이 아니다.
3. **웹/PWA 공개:** 미해결 P0/P1 없음, 데이터/계정 분리·필수 TC·복원·비용 관찰·지원 대응을 확인한 소스로 공개한다. 수익 기능은 없어도 된다.
4. **Android:** 실제 기기 인증 복귀와 설치 경험을 검증한 뒤 Play의 해당 계정 요건에 맞춰 내부/비공개 테스트를 진행한다. 신규 개인 계정의 12명·14일 연속 참여 요건은 계정 생성일 등 적용 조건을 확인한다. [Google 공식 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)
5. **iOS:** Android 피드백을 반영하고 실제 앱 효용·인증·삭제·접근성을 확인한 뒤 TestFlight와 심사를 진행한다. [Apple TestFlight](https://developer.apple.com/testflight/)

출시 알림은 한 번의 대규모 홍보보다 준비된 기능과 지원 범위에 맞춰 단계별로 한다. 모집·게시 문구는 [준비물](marketing/launch-kit.md)을 사용하되 실제 공개 URL·지원 연락처가 준비되기 전에는 배포하지 않는다. 사용자의 기록·지인·이메일을 홍보 소재로 사용하지 않는다.

## 현재 미정인 운영 입력

2026-10-19 사용자가 운영 형태·지원 이메일·도메인·월 운영비 상한·Google Play/Apple 개발자 계정 보유 여부를 모두 미정이라고 답했다. 임의로 사업자·이메일·도메인을 확정하거나 과금하지 않는다. 코드·로컬 검증·리뷰·PR·병합은 독립적으로 계속한다. 실제 서비스 개설과 외부 로그인/메일 설정·스토어 등록·공개 배포 때는 실제 입력이 필요하다.

수익화는 [무료·광고 비교 기록](free-with-ads-plan.md)에 보존하며 출시 후 실제 이용을 보고 다시 검토한다. 사용자 모집을 위한 마케팅 광고 지출도 현재 0원 제안이다. 현재 개발 상태는 [진행표](development/backlog.md)를 따른다.

# W09-E 공유 칭찬 대상·초안·늦은 응답 보호

2026-11-17 / F-01·G-07 최소 범위 / REQ-004·REQ-006 / POL-PRAISE-001·POL-SEC-001 / TC-PEER-RETRY-001

사용자는 공유판 A의 문구를 작성하거나 전송한 뒤 B판으로 이동해도 A의 초안·요청·늦은 응답이 B에 섞이지 않아야 한다. 일반 멱등 도우미와 DB/API 계약·권한·집계는 유지한다.

## 구현 범위

- 탭 메모리의 초안·시도·오류를 판 ID로 구분한다. 계정의 앱 인스턴스가 끝나면 상태를 폐기하며 브라우저 저장소에 기록하지 않는다.
- 최초 전송의 판 ID·본문·키를 함께 고정한다. 408·429·5xx·네트워크 오류는 그 판에서 같은 시도로 재확인한다. 다른 판은 별도의 초안과 요청 키를 사용한다.
- 동기 실행 가드로 같은 틱의 중복 submit을 막고, 전송 중 판·주요 메뉴 이동을 막는다.
- 판 열기·목록·칭찬 조회의 순번을 확인한다. 화면 이동·새 판 선택 뒤의 과거 응답은 현재 판이나 개인 기록을 덮어쓰지 않는다.
- 성공한 쓰기와 이후 조회 실패를 구분한다. 저장 성공이 확인됐으면 후속 읽기 오류 때문에 해당 쓰기를 다시 제출하지 않는다.
- 권한 회수 오류를 목록 새로고침이 즉시 지우지 않게 한다. 확정 거절은 시도를 해제하되 본인 입력을 보존한다.

## 검증

Playwright 1.65.1로 실제 데스크톱·모바일 폭 브라우저에서 동작을 검사한다. 별도 loopback 서버는 개발 환경·실행 모드·DB 주소 검사를 유지하며 실제 env·fixture 자격증명을 읽지 않는다. 모든 제품 API는 합성 응답으로 가로채 DB 쓰기 없이 검사한다. 이 결과를 실제 Auth/DB E2E·Google·물리 기기 수락으로 기록하지 않는다.

전송 전 A/B 초안, 페이지 재진입, 최초 미도달·커밋 후 응답 유실·429·503, 중복 form 이벤트, 늦은 A 조회와 성공 후 재조회, 권한 회수, 403·404·409를 검사한다. 일반 check·빌드·보안 HTTP와 관련 개인 칭찬·연결 API/DB 검사를 함께 확인한다. 실행 결과와 미실행 경계는 [증거](../quality/reports/w09-e-shared-praise-recovery-check-2026-11-17.json)에 기록한다.

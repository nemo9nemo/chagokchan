# W26 판 로딩 성능 개선

2026-10-26 사용자 요청 / REQ-002·NFR-001·NFR-003·NFR-005 / POL-ACCESS-001·POL-API-001·POL-SEC-001 / TC-PERF-BOARD-001

개발 서버의 최초 판 상세 요청 10.8초 중 10.7초가 경로 컴파일이고 실제 요청 처리는 97ms였다. 별도의 읽기 전용 로컬 반복 측정에서 목록→상세→개인/공유 회차까지의 준비된 경로 중앙값은 약 390ms였다. 이 수치는 현재 기존 판·로컬 개발 환경 기준이며 공개 환경이나 최대 용량 부하 수락 결과가 아니다.

기존 목록은 카드별 상세를 별도 요청하고 모든 상세 요청이 끝난 뒤 카드 정보를 반영했다. 판을 열 때도 모든 판의 과거 회차를 기다린 뒤 현재 판·기록을 표시했다. 이를 다음과 같이 개선한다.

1. 소유자 전용 `GET /goal-overviews` 및 `list_goal_overviews` RPC로 제한된 목록과 현재 개인/공유판·회차를 한 응답에 제공한다. 기존 목록/상세 RPC를 재사용해 권한·현재 세션·삭제/상태/커서·필드를 보존한다. HTTP N+1을 없애는 변경이며 DB 내부의 제한된 기존 함수 호출을 숨기거나 없앴다고 주장하지 않는다. 기존 `/goals`는 유지한다.
2. 판을 열 때 신선한 상세 권한 확인 후 현재 회차를 표시하고 칭찬을 먼저 조회한다. 과거 회차는 뒤에서 조회하고 그 실패로 현재 판을 지우지 않는다. 과거 회차 딥링크는 선택한 판만 필요한 페이지까지 확인한다. 이전 요청의 늦은 응답·기록 혼합을 막는다.
3. 로컬 실행 시에만 주요 읽기 경로를 GET으로 미리 준비한다. loopback·개발 모드·로컬 DB 조건을 모두 확인하고 사용자 데이터나 인증 값을 로그에 쓰지 않는다. `LOCAL_DEV_WARMUP=0`으로 끌 수 있다. production 인증/캐시 정책은 바꾸지 않는다.

새 SQL만 적용하며 기존 52개 마이그레이션과 기록을 수정하지 않는다. DB 16항목과 API/클라이언트 지연·경합/실패·개발 모드 차단 검사를 추가하고, 같은 로컬 판의 API 수와 시간을 전후 비교한다. 실제 브라우저에서 목록·현재 판·지난 회차를 확인한다. 2026-10-26 computer-use의 앱 제어 승인이 시간 초과되어 실제 브라우저 확인은 미실행이며, HTTP/상태 전이 검사와 분리해 W15에 남긴다. 진행 상태와 수락 범위는 [진행표](../development/backlog.md)에 기록한다.

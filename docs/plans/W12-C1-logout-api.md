# W12-C1 활성 세션 로그아웃 서버 경계

2026-10-26 / REQ-001·NFR-001 / POL-ACCOUNT-002·POL-SEC-001

W26 성능 개선 다음으로, 외부 Google/메일 설정과 독립적으로 기존 `POST /auth/logout` 계약을 구현한다. 기본 current는 현재 기기, all은 현재 사용자의 모든 세션이다. 사용자 ID·토큰·역할은 본문에서 받지 않으며 암호화 서버 쿠키·Auth 검증·현재 DB 세션 문맥을 사용한다. 일반 호출은 publishable key와 해당 사용자의 JWT만 쓴다.

Origin·Fetch Metadata·서명 CSRF·JSON/32KB·scope 검증 후 Auth의 local/global 폐기를 호출한다. 성공한 뒤 Auth/CSRF 쿠키를 각각 제거하고 no-store `{ok:true}`를 반환한다. 전송 장애나 확인할 수 없는 폐기는 성공 처리하거나 쿠키부터 지우지 않는다. all은 반드시 살아 있는 현재 DB 세션을 요구한다. 이미 폐기된 JWT로 다른 기기의 세션을 끝낼 수 없어야 한다.

current의 반복 요청은 이미 끝난 현재 세션임을 DB와 Auth 응답으로 확인한 경우에만 쿠키를 정리한다. 쿠키 자체가 없거나 잘못된 current 요청은 현재 브라우저 정리만 수행한다. 유효한 암호화 쿠키가 있으나 접근 토큰 만료 등으로 Auth 검증이 안 되는 경우에는 401을 반환하며 폐기 성공을 주장하지 않는다. 이 만료 경로는 앞으로 갱신 경합 처리와 연결해야 한다. 가입 전·삭제 중 계정도 제품 계정 활성화와 별개로 자신의 유효한 Auth 세션을 끝낼 수 있다.

개발 가상 로그인에서는 409로 거절해 개발 세션을 끊지 않고 로그인/로그아웃 UI도 추가하지 않는다. 실제 Google/OTP·가입 UI·갱신·초대 복귀·재인증/탈퇴·운영 분산 제한은 여전히 W12-C/D·W13~W15다.

단위 검사와 폐기 가능한 새 로컬 Auth 사용자 두 명의 여러 발급 세션으로 current/all·다른 사용자 보존·폐기 JWT 재사용·기존 데이터/세션 보존을 확인한다. 관리 키는 로컬 테스트 사용자 생성/정리만 사용하며 제품/API 호출에는 사용하지 않는다. 실제 제공자·HTTPS 쿠키/브라우저 로그인 수락 완료로 표시하지 않는다.

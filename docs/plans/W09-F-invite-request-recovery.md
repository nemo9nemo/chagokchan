# W09-F 초대 연결 요청 전송·재시도 분리

2026-11-17 / F-02 / REQ-005 / POL-CONNECT-001·POL-SEC-001 / TC-INVITE-RETRY-001

전송 중인 요청과 결과가 불확실해 재시도 정보를 보유한 요청을 구분한다. 실패 뒤에도 원래 초대·본문·키로 다시 확인할 수 있고, 새 코드나 늦은 미리보기 응답이 이전 요청과 섞이지 않아야 한다.

- 미리보기가 성공한 초대 비밀의 메모리 스냅샷을 요청 대상으로 사용한다. 코드 입력 변경은 기존 미리보기를 해제하고 다시 확인하게 한다.
- 전송 중에만 전송 버튼을 비활성화하고 같은 틱의 중복 실행을 ref 가드로 막는다. 전송 중에는 코드·초대 선택·취소·주요 화면 이동을 막는다.
- 네트워크·408·429·5xx에는 시도·본문·키를 보존한다. 재시도 보유 상태에서는 같은 요청 재전송을 허용하고 코드 변경·새 미리보기는 막는다.
- 결과가 불확실한 초대 정보를 닫을 때 이미 접수된 요청의 철회와 다름을 확인한다. 실제 철회는 요청 목록의 기존 철회 경로를 사용한다.
- 미리보기 순번을 확인해 다른 코드 입력·취소·앱 종료 뒤의 과거 응답을 무시한다. 성공 처리와 이후 목록 조회를 구분한다.

Playwright의 합성 API 응답으로 코드/링크·미도달/응답 유실/429/503·새 코드·취소·중복 submit·늦은 미리보기·확정 거절을 데스크톱/모바일에서 검사한다. 같은 suite에서 W09-E의 26건도 계속 검사하고 공통 unit·build·실제 로컬 연결 RPC/API 경계를 재검증한다. 실제 Google·운영 DB 수락과 구분한다.

# W12-C2 — 초기 웹 베타 Google 로그인·가입·세션 갱신

2026-11-09 / 사용자 11-03 범위 결정: Google만 제공, 이메일 OTP는 발신 설정 준비 뒤 유예. 개인·무료 우선·플랫폼 기본 주소를 사용한다.

관련 REQ-001/005/011·NFR-001/004/005, POL-ACCOUNT-001/002·POL-SEC-001·POL-AUDIENCE-001. 실제 Google 제공자/기기 수락과 서버 단위·로컬 Auth 검사를 구분한다.

## 구현과 보안 경계

- 로그인 시작은 Origin·서명 CSRF·JSON 상한을 검사한 POST다. Google PKCE verifier는 짧은 수명의 별도 암호화 Host/HttpOnly/Secure 쿠키에만 보관한다. 코드 교환은 서버에서 수행하며 토큰/PKCE 원문을 브라우저 JSON·저장소·로그에 넣지 않는다.
- 기존 세션과 로그인 흐름을 묶어 늦은 콜백이 다른 계정 로그인을 덮지 못하게 한다. 콜백의 중복/만료/오류/변조를 거절하고 고정된 같은 앱 경로로 복귀한다. 서버가 실제 Auth 사용자와 현재 DB 세션/가입 상태를 확인한 뒤 Auth 쿠키를 발급한다.
- 가입 전에는 명시적 만 19세 이상 확인 화면을 보여 주고 기존 bootstrap API로 계정을 생성한다. 로컬 가상 사용자 모드는 기존 경험을 유지한다.
- 갱신은 별도 POST·CSRF로만 수행한다. Auth의 새 토큰과 기존 사용자/세션을 비교하고 DB 현재 상태를 재확인한다. 쿠키의 원래 최대 수명을 보존한다. 갱신/로그아웃 경합 뒤 폐기 세션으로 업무 API를 호출할 수 없어야 한다.
- 로그인/초대/사용자별 HTML·RSC/API는 no-store, 인증 화면은 noindex를 적용한다. 초대 fragment는 로그인 중 서버가 보호하는 임시 경로로 보존하고 URL/분석 로그에 재노출하지 않는다.
- Google 최소 식별 범위만 요청하며 브라우저 Supabase 클라이언트나 서비스 역할 키를 추가하지 않는다. 전역 요청 제한/봇 방어는 운영 설정과 함께 검증한다.

## 완료 기준

코드/쿠키 변조·다른 흐름/세션·중복/취소·외부 next·CSRF·만료·다른 사용자/세션 갱신·재시도/장애를 단위 검사한다. 로그인/가입/로그아웃 UI와 HTTP/CSP/캐시 회귀, 실제 Google 콜백·여러 계정·초대 복귀를 별도 실행한다. 실제 제공자 설정이 없으면 미실행으로 남기며 공개 완료로 표시하지 않는다. 탈퇴 재인증·파기/복원은 W12-D/W14/W15에서 이어간다.

## 11-09 범위별 결과

W12-C2a의 코드·서버/실제 로컬 Auth·비로그인 렌더 검사는 [보고서](../quality/reports/w12-c2-google-web-auth-check-2026-11-09.json)에 기록한다. PKCE 교환은 고정 Supabase Auth `/authorize`·`/token?grant_type=pkce` 프로토콜을 사용하며 pinned Auth SDK의 요청 형식과 [SSR 고급 안내](https://supabase.com/docs/guides/auth/server-side/advanced-guide)를 확인했다. 일반 요청은 기존 검증된 사용자 JWT 클라이언트다. W12-C2b의 실제 Google/HTTPS 수락은 별도이며 미완료다. 공개 정책 페이지는 W27-C, 탈퇴는 W12-D에서 연결한다.

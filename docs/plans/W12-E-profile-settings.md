# W12-E 본인 표시 이름·아바타와 공유 상대 구분

2026-11-17 / F-03 / REQ-001·REQ-005·REQ-006 / POL-ACCESS-001·POL-LIMIT-001·POL-CONNECT-001 / TC-PROFILE-001·002

기존 OpenAPI의 미구현 PATCH /me를 닉네임·아바타 범위로 구현한다. 시간대 변경은 별도 후속으로 남기고 첫 베타 입력 계약에서 제외한다. 가입·성인 확인 정책 버전은 변경하지 않는다. [결정](../decisions/ADR-0012-self-profile-settings.md).

## 범위와 수락

- 본인의 현재 세션·active 계정을 검증한 업무 RPC만 프로필을 갱신한다. 수정 대상 UUID·성인 확인·시간대·권한 입력을 받지 않는다.
- 닉네임은 NFC·양 끝 ASCII 공백 정리 후 1~20 코드포인트, 제어 문자·공백만 있는 값 금지다. 아바타는 기존 grape/leaf/star 목록이다. 같은 닉네임은 허용한다.
- 선택한 필드만 수정하고, 같은 필드 동시 수정은 마지막으로 커밋한 값으로 정한다. 계정 삭제와 같은 advisory namespace를 사용해 접근 차단 이후의 갱신을 거절한다. 사용자별 분당 10회와 제한기 장애 시 차단을 적용한다.
- 가입 기본값·기존 계정·Google 메일/실명은 자동 변경하지 않는다. 개인 기록은 프로필 설정 없이 사용할 수 있다. 연결 화면에서 요청에 표시될 본인 이름을 확인하고 수정할 수 있게 한다.
- 동명이인 구분을 위해 이미 허용된 UUID 응답의 마지막 12자리에서 만든 보조 표시를 사용한다. 초대 미리보기에는 전체 UUID 대신 같은 보조 표시만 추가한다. 이 표시는 인증·전역 고유성·권한 판정 수단이 아니며 초대 출처 확인을 대신하지 않는다.
- 프로필·초대·연결/권한 화면에서 보조 표시를 함께 보여준다. 이메일·전체 UUID·다른 사람의 개인 기록을 추가 노출하지 않는다.

## 검증·반영 순서

정책/계약·새 마이그레이션 → 로컬 DB 적용·pgTAP·실제 발급 Auth/동시성·삭제/세션 회수·보존 검사 → 서버/API·화면·브라우저 회귀 → check/build/HTTP·직접 검토·PR/필수 CI 순으로 진행한다. 새 SQL은 기존 56개에 추가하며 적용한 파일을 고치지 않는다. 호스팅 DB를 준비하기 전 의존 웹을 배포하지 않는다.

타인 수정 거절·직접 DML/익명 RPC 거절·정규화/상한/빈 입력/알 수 없는 필드·같은/다른 필드 동시 수정·삭제 경합·갱신 실패 입력 보존·동일 닉네임의 초대/권한 대상 구분·기존 공유/초대 회귀를 검사한다. 실제 Google·HTTPS/물리 기기는 W13/W15 수락으로 분리한다.

로컬 적용 SQL은 총 58개다. 첫 프로필 SQL의 초대 projection 확장을 후속 `20261117124012_profile_preview_backward_compatibility.sql`로 복구했다. 기존 `preview_connection_invite`는 두 필드를 유지하고 신규 BFF는 `preview_connection_invite_with_profile`의 세 필드를 사용한다. 호스팅에서는 두 신규 SQL을 한 원자적 배치로 적용한 뒤 새 웹을 배포해야 한다. 첫 SQL만 적용한 중간 상태로 트래픽을 받지 않는다.

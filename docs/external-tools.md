# 외부 도구 사용과 연결 순서

정리일: 2026-10-07 / 상태: 외부 도구 사용 허용, 연결 상태 확인 및 실행 순서 정리

사용자가 외부 도구 연결을 허용했다. 현재 기획·ERD 작업에 필요한 도구부터 사용하고, 구현용 서비스는 [구현 전 결정](pre-implementation-plan.md)과 [배포 계획](deployment-and-git.md)에 맞춰 연결한다. 앱 구현과 Git 연결은 기존 계획의 후속 단계다.

## 도구별 용도와 현재 상태

| 도구 | 용도 | 이번에 확인한 상태 | 연결 시점 |
| --- | --- | --- | --- |
| Miro | 기획 흐름도, ERD 검토, 결정사항·의견 정리 | 사용 가능한 플러그인 확인, 설치 제안. 설치·계정 인증 완료는 아직 확인 전 | 현재 기획 단계에서 사용 가능 |
| GitHub | 문서·소스·마이그레이션 형상관리, PR·CI | 플러그인 설치 확인. 이 작업 폴더의 Git 저장소·원격은 아직 없음 | 사용자가 계획한 추후 Git 연결 단계 |
| Supabase | 구현 이후 스키마·권한·Auth 설정 검토, 개발 환경 관리 | 사용 가능한 플러그인 확인, 미설치 | 로컬 DB 설계·검증 후 스테이징 연결 단계 |
| Vercel | 스테이징·운영 배포와 상태 확인 | 사용 가능한 플러그인 확인, 미설치 | 로컬 빌드·검증 후 스테이징 배포 단계 |

플러그인 설치, 계정 인증, 특정 프로젝트 접근, 실제 저장소·서비스 생성은 서로 다른 상태다. 설치 여부만으로 계정이나 프로젝트에 접근할 수 있다고 간주하지 않는다. 연결 시 이 표에 실제 확인 결과와 날짜를 갱신한다.

## Miro를 사용할 때의 기준

1. 설치·계정 인증 후 사용할 팀과 보드의 접근 범위를 확인한다.
2. [핵심](diagrams/data-erd-core.mmd), [연결](diagrams/data-erd-connections.mmd), [운영](diagrams/data-erd-operations.mmd) ERD를 각각 검토할 영역으로 나누고, [ERD 문서](data-erd.md)의 관계·제약 설명을 함께 둔다.
3. 확정한 정책과 미결정 항목 I01~I09를 구분해 표시한다. 보드에서 합의한 변경은 로컬 문서와 Mermaid 원본에 반영한다.
4. 보드 주소·접근 범위·기준 문서 버전을 기록하고, 검토를 마친 결과는 로컬 문서에서도 확인할 수 있게 유지한다.

ERD의 기준 원본은 docs/diagrams/*.mmd와 [관계·제약 문서](data-erd.md)다. Miro는 검토용으로 사용하며, 시각적인 선 이동만으로 DB 제약이 변경되었다고 판단하지 않는다.

Miro의 Mermaid 기능은 베타이며 공식 도움말은 ER 다이어그램의 시각 편집을 아직 출시 예정으로 표시한다. 연결 후 실제 지원 범위를 확인하고, 필요하면 Mermaid를 렌더링한 도표와 별도 의견을 함께 배치한다. ERD가 편집 가능한 개별 도형으로 자동 변환된다고 보장하지 않는다. [Miro Mermaid 지원 범위](https://help.miro.com/hc/en-us/articles/7004628130962-Create-Mermaid-diagrams-Beta)

Free 플랜의 보드는 팀 전체에 공유되며 팀 공유를 끌 수 없다. 사용할 팀의 구성원을 먼저 확인하고 공개 링크는 활성화하지 않는다. 개인 비공개 보드가 필요하면 기존 이용 플랜의 지원 여부를 확인한다. 이 기획 작업을 위해 유료 가입을 필수로 정하지 않는다. [Miro 보드 접근 범위](https://help.miro.com/hc/en-us/articles/360011114519-Public-boards-vs-private-boards)

## 개발 서비스 연결 기준

개발 도구의 계정 인증과 앱 사용자의 Google·이메일 로그인은 별개다. 앱에서 지인을 연결하는 방식도 개발 서비스의 OAuth 권한과 독립적으로 유지한다.

| 연결 대상 | 접근 기준 | 기록할 항목 |
| --- | --- | --- |
| GitHub | 해당 비공개 저장소에 필요한 접근만 부여 | 소유자·저장소 주소·기본 브랜치·보호 규칙 |
| Supabase | 환경·프로젝트를 지정하고 스키마 변경은 검토된 마이그레이션으로 관리 | 조직·프로젝트 식별자·리전·환경·적용 마이그레이션 |
| Vercel | 환경·프로젝트를 지정하고 배포 순서는 기존 운영 절차를 따름 | 팀·프로젝트 식별자·환경·배포 ID·도메인 |
| Miro | 지정한 기획 보드의 문서와 설계 정보 사용 | 팀·보드 주소·접근 범위·기준 문서 버전 |

외부 기획 보드에는 스키마·가상 예시·결정사항을 올린다. 관리 토큰·환경변수 비밀값·실제 사용자 기록은 기획 자료에 포함하지 않는다. 프로젝트 식별자는 기록하되 비밀값은 [환경별 비밀 관리](deployment-and-git.md)에 따른다.

실제 연결 후에는 접근 가능한 프로젝트를 확인한 결과를 남긴다. 배포와 DB 변경은 연결 자체의 결과로 실행하지 않고, 해당 구현·릴리스 작업의 검토된 변경과 연결해 수행한다.

## 다음 작업

현재는 Miro 설치·계정 인증이 완료되면 기획 보드 작업을 진행할 수 있다. 완료 여부가 확인될 때까지 기존 로컬 ERD와 문서가 유효한 결과물이다. Supabase·Vercel 프로젝트 연결과 Git 저장소 생성은 각각 위 단계에 도달했을 때 진행한다.
